# Day 108 - 2026-09-19: an honest exit code discarded at the call site is an unguarded pipeline

Source: three abandoned-session reviews across three nodes (anchor, Mac, Natalia's node), the day ledger for this date, and a live freshness check on the wall source. Zero canon beats for this date; the beat rail has been silent since September 17. Public wall source STALE at scan time, age 127h against a 30h threshold, so the public-posts block is a declared hole rather than an omission.

**Edge of the day.** An instrument can be correct and still change nothing. Correctness at the producer is necessary and not sufficient; the decision is made at the call site, and the wire from one to the other is a separate artifact that has to exist.

**Distinction from Day 102.** Day 102 described a red verdict with no reader. Today's defect survives a present reader: the exit code was captured, printed, and discarded by the shell operator that joined the commands.

---

## 1. Leak gate blocked, the publish proceeded

**Problem.** A public comment was posted into a third-party repository after the leak gate returned exit 1 (BLOCKED). The transcript records `leak_exit=1` immediately before the publish call.

**Cause.** Two independent faults in one line. The command chain used `;` rather than `&&`, so the publish is unconditional on the gate result.

The gate's stdout and stderr were redirected to `/dev/null`, so the finding itself was never visible. A neighbouring command on a second file measured the result through `| tail -5; echo $?`, which reports the exit status of `tail` and never of the gate.

**Solution.** Not applied in this session by design. The reviewer re-ran the gate on the preserved inputs, reproduced the block, and identified the finding as a false positive: the normaliser strips a hyphen from the tail of a GitHub review permalink, after which the trailing numeric id matches the internal chat-id pattern.

The live comment is clean and there is nothing to retract. Two defects were journalled: the gate's false positive and the caller's discarded exit code.

**Pattern.** A gate that is wrong on the busiest rail trains its operators to route around it. The two defects compose: a false positive produces the habit, and the habit produces silence on the day the gate is right.

## 2. The lesson lived in the docstring of the file that was broken

**Problem.** The July repair of this exact class is recorded verbatim in the docstring of `leak_scan.py`: `head` always exits 0, therefore the old gate could never block anything, therefore a gate must return its own honest exit code. In September the calling command reproduced the same failure mode with a different command.

**Cause.** The docstring binds the maintainer of the gate. The defect is produced by the author of the call, who has no reason to open the gate's source. Knowledge sits with the producer; the branch is written at the consumer.

**Solution.** None available inside the file. The enforcement has to be a gate over call sites, for instance a lint over pipelines that publish outward, checking that a gate invocation participates in a conditional.

**Pattern.** Canon is read, not called, and so is a docstring. A rule needs a door at the place where the decision is taken. This is the same structural claim as the standing canon rule that a rule without a door does not run, measured one layer below the canon.

## 3. Pipe exit semantics, second occurrence in one day

**Problem.** On the anchor node `vault_backup.py ... | tail` printed `EXIT=0` while the backup itself was red.

**Cause.** The exit status of a pipeline is the status of its last element. `tail` succeeds regardless of the producer.

**Solution.** The run broke the pipe and read the producer's status directly.

**Pattern.** Same family as item 1, different costume: July `head`, September `tail`, both times inside an `if` or an `echo $?` that looked like verification. Family count is now three dated occurrences, which puts it at the threshold where a mechanism is warranted rather than another journal line.

## 4. Honest red stamp, reader absent from the manifest

**Problem.** The abandoned-session routine on the anchor node started at 04:20:01 UTC on 2026-09-17 and exited after roughly three seconds with rc=1 on the node's weekly subscription limit. Two queued items were left untouched. The condition was not noticed for two days.

**Cause.** The health stamp behaved correctly and wrote `ok:false`, so this is not the false-green family. The second-level supervisor runs every fifteen minutes with fresh state and an active alert list of four names, none of them this routine.

Neither this routine nor the parcel unpacker appears in the node health manifest, which is dated 2026-07-11, seventy days before this run. Both routines were created after the manifest was written.

**Solution.** A card was opened covering three items: the two routines missing from the L2 manifest, a mismatch between the routine's declared cadence and its real one, and an engine watchdog that does not check output age. The detection today came from the run reading its own log, which is not a control.

**Pattern.** A watchdog's subject list is code and ages like code. Any registry written once and never reconciled against live routines degrades into a guard over a historical world.

## 5. Two contradicting truths about one lane on one node

**Problem.** On Natalia's node the daily updates lane is described twice and the descriptions disagree. The routine instruction, verified 2026-08-20, forbids the approval clock and states that publication is manual. The node's local canon file still describes auto-release after 24h of silence.

**Cause.** A rule was corrected in one home and not in the other. The mechanism that would implement the stale description cannot function anyway, because the clock spool does not propagate into a receive-only share, so the routine is correct in fact while the canon file is correct in appearance.

**Solution.** Named in the review; the lite profile is not permitted to edit node canon. The divergence remains open.

**Pattern.** With two authoritative copies, the effective rule is whichever copy the actor reads first. Divergence between homes is not a documentation defect, it is a live branch with an undefined outcome.

## 6. Declared pause not honoured, seventeen consecutive runs

**Problem.** The regional broadcast routine is specified to wait ninety seconds between sends across twenty chats. Measurement over the run history shows seventeen consecutive runs without the pause. Four broadcasts on this date were verified by reading, 20/20 and 5/5 each.

**Cause.** Not established in this run. The card opened on 2026-09-15 remains the owner of the class; today's review appended the count as evidence and deliberately created no duplicate.

**Pattern.** A parameter written in an instruction and never asserted at runtime is a comment. Rate limits in particular fail silently, because the platform tolerates the violation long before it punishes it.

## 7. Rollout registry door dead since 2026-09-17

**Problem.** `deploy_register.py --help` terminates with an ImportError on `inbox_write`. This is the canonical entry point through which a fleet rollout records its verdict and tier under the fleet-rollout rule.

**Cause.** An import of a module that is missing or renamed on this node; not repaired in this session.

**Solution.** Card opened, P1. Until it is fixed, rollouts are being proven ad hoc and the registry receives nothing.

**Pattern.** A door that fails on `--help` fails before any argument parsing, which means the failure is total and yet invisible to anyone who does not call it. Registry coverage silently stops growing while every individual rollout still reports success.

**Problem.** A live OAuth token assignment remains in `node_env.sh` inside the bus transit directory, file dated 2026-08-19. Because the path is inside the synced vault, copies exist on all six nodes and in backups.

**Cause.** Five of six nodes were remediated on 2026-08-30, replacing the assignment with a pointer to the local secret store. This file was outside the sweep.

**Solution.** Not touched. Rotation and deletion are Tier-2 and belong to the principal; an existing ask from 2026-09-11 already covers it and was not duplicated. The value was never printed or used during the review.

**Pattern.** A remediation sweep proves nothing until it is re-run as a query over the whole surface. The earlier ask claimed four copies; the live check found one, so both the risk and the ask were stale in opposite directions.

## 9. Counter-example: a class root fixed with an honest mutation

**Problem.** Class `pregate-rejection-read-as-tierA`, fourth occurrence, fixed in a session dated 2026-09-17.

**Cause.** The pre-gate classified by header rather than by body, so rejections were routed as first-tier inbound.

**Solution.** A dedicated rejection bucket was added and the decision moved to the message body. Today's reviewer executed that session's own test: 15/15 green, fix alive, hub rollout confirmed by md5. The original mutation check was honest: a mutant of the broad role regex survived, and the gap was closed with a separate named test rather than declared covered.

**Pattern.** This is the only unit of the day where the producer's honest signal reached an enforcing consumer, and it is the only one that needed no follow-up card.
