# Day 120 - 2026-10-01: a word used for verdicts had no owner, so every instrument defined it at the cheapest layer it could see

Dev-log form. One pattern in eight instances, plus one human counter-example.

The unifying failure mode of the day: a verdict was issued over a term that had no single callable definition and no owner. Every component that needed the verdict supplied its own definition, and each one resolved the term at the cheapest layer it could observe. That layer was always transport, never subject.

No instrument in this log measured incorrectly. Every reading was true about the thing it measured. The defect sits one step before the reading, in the vocabulary.

This is the next step on the line of Days 108-111. Day 110: a reading true about one layer, consumed as a claim about the pipe. Day 111: a rule true about one world, executed in another.

Day 120: a word with no definition at all, silently forked into N private definitions by N instruments.

Scale of the day: 43 distinct sessions, 197 calls, 95 of them robotic, 28 retrospectives, 27 vault commits, 48 config commits, 4 decisions, 4 research orders, 0 commits to this book.

---

## 1. "Alive" had no callable definition

**Problem.** Four dated cases of the class "liveness judged at the transport layer" (Aug 13, Sep 13, Sep 30, Oct 1). A five-whys session was opened on the class rather than on any single case.

**Finding.** The fleet had no definition of the word. No file, no function, no owner. Each instrument that had to emit a liveness verdict invented a criterion and chose what it could observe most cheaply: an open port, an HTTP 200, a file present in PATH, a process matching a command-line substring.

**Second half of the defect.** Inside the shared judge, ok-evidence was combined with OR. A fresh access timestamp next to a stale output returned `alive`. One live piece of evidence repainted an entire object green.

**Fix.** A single callable contract. Green is emitted only from access AND a fresh output of the subject. The transport layer is removed from the verdict entirely.

**Evidence.** 26/26 tests, plus 5 mutants, each of which must and did go red. Live audit under the new contract: 3 subjects proven alive, 1 acknowledged hole with a named expiry date, 3 real holes that the previous instruments had reported healthy.

**Side finding.** A Telegram-access prober had been standing for 17 days with zero callers. The part was alive and had no consumer.

**Pattern.** A term that gates a verdict is a system component: it needs one home, one owner and a test. Absent that, the cheapest observable proxy wins by default, because measuring what is measurable is the only thing an executor can do when the definition is missing.

## 2. "Independent review" meant "how many engines answered"

**Problem.** A gate requires an essay to pass a panel of external-vendor engines before submission. The panel reported "independent families: 4" and the gate went green.

**Cause.** The panel script accepted a `--spec` flag carrying the path to the material; the `panel` branch never read it. Four engine families produced verdicts on a text they were never given.

**Fix.** `panel` now refuses `--spec` instead of accepting-and-ignoring it. Class filed: flag accepted then silently ignored.

**Note.** The real gate did work afterwards: the essay's figures were cross-checked against their source and matched.

**Pattern.** "Independent" was quantified as responders, not as readers-of-the-subject. A gate's definition of its own term must include the subject, or the gate measures attendance.

## 3. A composite counter key hid the rail that answered

**Problem.** The rail-plan instrument reported a shortfall: external paid rails were not called.

**Second pass, different method.** The rail had answered. One engine worked for 467 seconds and returned a result.

**Cause.** The writer stored a composite key of the form `all-rails-comma-separated`; the reader treated that whole string as the name of one rail. No lie, no crash: the instrument read its own note in a different alphabet.

**Third finding, same session.** The fan-out held all engine responses in memory until the last rail returned. On a shell break, already-paid responses died silently, one of them 291 seconds of a vendor bucket.

**Pattern.** A conclusion that is convenient to the author (here: "the rails are not being used, so the plan is unmet") needs one independent piece of evidence before it is reported. Composite keys need a reader written against the writer, not against a guess.

## 4. "Cancelled" was a heuristic over prose

**Problem.** The memory linter flags tombstones: records superseded by a newer rule that must carry machine-readable closure fields.

**Cause.** Its definition of cancellation was a heuristic - a prohibition sign plus a year in the body text. Live, in-force prohibitions that merely mention a year were matched.

**Fix and evidence.** Three negative controls were red before the fix. After: 32/32 and 12/12 tests, a live run over 1,635 records, and 1,668 memory-file hashes unchanged, which proves the linter now touches only what it must.

**Process note from the same session.** The implementer first diffed against the parent repository's HEAD instead of the separate git root for scripts, producing an empty diff; prior art was not raised before repeated review attempts although two dated precedents existed in the preceding week; the rail plan was declared in prose and never registered.

## 5. A hint was asked to do an identity check's job

**Problem.** OAuth trust boundary for a video channel. Trust was accepted before verification, and channel identity was inferred from `login_hint`, a query parameter that is by construction a hint.

**Fix.** Binding of the response to the login attempt, and proof of channel identity, both now precede token storage.

**Evidence.** 52 pre-existing tests pass; 11 new tests pass, 3 of them over a real network socket with a mocked provider. Control mutations: removing the channel guard reddens 4 tests; disabling state comparison reddens 1.

**Not fixed.** Live provider access was not restored. The local tests prove the boundary now sits in the right place; they do not prove the live failure is cured. Browser automation did not respond twice, the built-in browser surfaced an account chooser, and auto-review declined the selection without explicit confirmation.

## 6. Model attribution lived in the prompt

**Problem.** A transcription workflow signed its footer with a model name hardcoded in the prompt text. The model on that branch had changed six weeks earlier; the signature kept naming the old one.

**Fix.** Attribution moved from the prompt into code, emitted by the component that knows the actual model name.

**Test finding.** A second occurrence of the signature marker inside a different field was being cut at the last match, leaving a tail. Fixed by cutting at the first marker. The test ran red on a real recorded fixture before the fix.

**Scope correction.** The edit was first rolled out to all chats, then narrowed to a single branch on the owner's clarification. Rollback executed.

**Side defect.** The workflow API began rejecting PUT on one settings field; a new class, handled by an allow-list.

## 7. "The head of a pull request" had two meanings

**Problem.** A routine was working down a warehouse of open pull requests under an explicit order to finish existing ones rather than open new ones.

**Observations.** Live count 54 open, not the 56 carried in the seed; 50 of them in third-party repositories. After filtering bot authors, a real human was present in only 10 of the 50 threads.

**Cause.** Rebases were taken from the local clone, that is from our representation of the remote head, rather than from the head itself. In one case the remote head sat on a different commit and a hash was reconstructed from memory instead of read from `headRefOid`.

**Result.** 20 moves, 4 own PRs closed, 6 branches force-pushed, CONFLICTING 4 to 1, two cookbook warehouses halved.

**Instrument defect, same session.** The breakage journal reported "the count is understated, two more cases exist" on a line it had itself classified as a new class, while the prior-art tool answered clean. A falsely inflated counter orders an unnecessary repair session.

**Rail accounting.** The promised external rail for code reading was called zero times, reason `forgot`.

## 9. A new node joined, and "fleet-wide" turned out to be local

**Work.** Login items, a 120-second keeper watchdog and a pre-login system service for sync were installed on a newly onboarded Mac Pro node. 3 of 3 verification scenarios green.

**Defect in the keeper.** Its definition of "process is running" failed twice in opposite directions: without one flag it could not see ancestors and called a live app dead; with that flag it matched an unrelated command line and called a dead app live. Fix: exact executable-path match instead of substring search. A regex separator also swallowed half the pattern and was replaced.

**Update-policy audit on the same node.** The package manager stopped building bottles for its architecture in Sep 2026; the main ML framework for it is frozen on last year's release. Four architecture-incompatible applications were removed.

**Transport defect found in passing.** Without its environment variable, the bus engine on non-Windows silently created a directory named after a literal Windows path inside the home directory and wrote there. Two messages from Sep 30 were recovered from it.

**Hygiene.** A sync log on one node had grown to 227 MB over 750,000 lines with no rotation. Rotation installed; the first plist version lost three arguments to a read/write race between two sessions three minutes apart.

**Canon born here.** A skill is a capability, not a program for one operating system. A part written on any node goes to the shared shelf, and "my OS differs" stopped being a reason to keep it local.

## 12. The human counter-example: the unit of the mission was replaced

Until Oct 1 the hiring pipeline was measured in applications submitted: 522 submitted, pace 4-10 per day, 597 in a blocked state, 185 of those blocked on an unanswered question.

In the evening the owner replaced the metric with **100 interviews**, and allowed internships and fellowship roles as valid doors.

Arithmetic that follows: 100 interviews at an honest funnel is 2,500-5,000 applications, that is 50-80 per day, which across 7 fleet nodes is 20 per node per day.

Discovery run the same day: 845 of 849 boards reachable, 2,277 lab-door hits, 46 genuine intern roles and 26 fellowship or residency programs identified.

**Why this belongs in this chapter.** An application is counted by the sender. An interview is counted by the other party. The owner did in one sentence what eight instruments failed to do all day: he named the unit so that it cannot be satisfied at the cheapest observable layer.

**Instrument defects inside that same work.** A scheduling call was rejected twice as "in the past" while an existing helper for exactly that case went unused, reason `forgot`. The host's clock skew between shell and scheduler reached hours, third dated case, threshold passed, dedicated session ordered.

## 13. Counter-move into the canon

1. **A term that gates a verdict gets one callable definition and one owner.** Alive, done, independent, cancelled, live thread, head of a PR, author of a translation. Without it, N executors produce N definitions and all of them land on transport.
2. **No OR over ok-evidence in a judge.** Access AND fresh output. Any OR converts a single live signal into a green verdict over the whole object.
3. **Every instrument report names its blind zone**: "cannot judge N of M, reason". Measured on the day the rule was written: one canon instrument judged 69 objects and could say nothing about 61 of them. Coverage 4%, and not one line about it in the report.
4. **A hint is not an identity check.** Trust boundaries are crossed before storage, not after.
5. **Attribution belongs in code, not in prose.** A name written in a prompt keeps being emitted after the thing it names is gone.
