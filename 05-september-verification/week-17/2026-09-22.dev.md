# Day 111 - 2026-09-22: a rule expires when its consumer changes, not when its text does

Dev-log form. One pattern in seven instances plus one counter-example.

The unifying failure mode of the day: every rule and every instrument in this log was correct at the time it was written, carried an unstated assumption about who or what it served, and continued executing correctly after that party changed. No text was edited, no component failed, no alarm was raised. The defect is the untracked assumption.

This is the sibling of Day 110. There, a reading true about one layer was consumed as a claim about the pipe. Here, a rule true about one world is executed in another.

---

## 1. Third agent enters a two-agent workspace

**Problem.** A third coding agent was onboarded into a workspace whose skill shelf, canon, memory and working folders are shared. Three enforcement holes surfaced immediately.

**Observations.**

Hole one: the new agent's hooks configuration is not executed by its runtime. Consequence: no automatic pre-work recall, and no participation in the write lease.

Hole two: the new agent's tool names were absent from the write guard's match table.

Hole three: one operation name differed by case and token shape from the spelling the guard was written against, so it fell through even where the family was covered.

**Cause.** The guard's coverage was enumerated against the set of agents present at authoring time. Enumeration is correct and complete until the set grows.

**Method note.** The holes were found by onboarding as an adversarial exercise rather than a walkthrough. A guided tour would have exercised only the paths the guard already knows.

**Side finding, same session.** A different-vendor reviewer found live secrets in the git history of one repository. History was rewritten twice: v1 rejected, v2 covering 2,618 files with zero secret classes remaining. Six breakage classes were filed in one session.

**Self-report.** A read-only restriction was introduced where a finished worktree-isolation mechanism already existed in the system. A restriction was built in front of an available door.

**Pattern.** Enforcement enumerated over actors expires when an actor is added. Guards should key on capability, not on a name list, or must carry an explicit "known actors" assertion that fails closed on an unknown one.

## 2. A routing rule became a leak when the bucket owner changed

**Problem.** The canon rule "burn the paid rails of other vendors before your own" was authored in August, when the personal Codex bucket was effectively unused. The rule routed a class of research work through the Codex command line.

**Observation.** 78 research dispatches through `codex exec` between 2026-08-06 and 2026-09-22, 67 of them successful, legs of 12 to 27 minutes each. Three of them on 2026-09-22 itself.

**Cause.** The fact that made the rule economical, an idle bucket, changed outside the rule. The owner began using that bucket for his own coding. The rule text did not change and did not need to; it simply started charging the wrong account.

**Fix.** Research legs are constrained to web subscriptions; the personal account's CLI is excluded from this work class. Parcel distributed to six nodes.

**Pattern.** A routing rule encodes an economic fact about a third party. Economic facts are not versioned by the rule that consumes them. Any rule whose justification is "this resource is idle" needs a scheduled re-check of that premise.

## 3. A safety net cut by category rather than by role

**Problem.** A fleet-wide deflation pass halved the frequency of background routines. The voice-transcription backstop was included because it is registered as a routine.

**Observation.** Backstop interval stretched from 4h to 8h. In the measured window: 84 voice notes, 83 transcribed by the primary bot, 1 missed at 12:25. The backstop did not catch the miss, because its grace period had grown wider than the interval in which the loss becomes visible to a human.

Family `instrument-lies-green`: 85th case since 2026-08-10. Test count for this component: 16 -> 43.

**Cause.** The registry stores category, not role. "Routine", "emergency watchdog" and "safety net" are the same row type, so a category-wide operation reached all three.

**Fix and rule.** A watchdog's frequency is derived from the consumer's deadline, not from a general permission to slow down. Zero token cost is an independent reason to exempt.

**Pattern.** Any bulk operation over a registry acts on whatever the registry can distinguish. If the registry cannot express role, bulk operations will cross role boundaries silently.

## 4. An acceptance invariant aged out overnight

**Problem.** The doorbell acceptance suite asserted byte-identity of files across a run. After the permanent production runner was enabled, the suite went red on legitimate activity.

**Observation.** A live production tick writes to the runtime state database and the usage counter by design. The invariant did not distinguish artifact files, which must not change, from runtime files, which must.

**Fix.** Invariant split by file role. Suite: 64 green + 42 red = 106 scenarios, exit 0. Scheduler overlap proven separately: foreign ticks 0, own ticks 1.

**Honest gap.** No independent review of this fix: the second-opinion tool fails to launch (`WinError 2`). Verdict recorded as incomplete rather than green.

**Pattern.** An invariant of the form "nothing changes" silently assumes the absence of an authorised concurrent writer. It must be restated as "nothing changes except what these named writers own" before any such writer is enabled.

## 5. Sync rollback, and a cure that sat in quarantine

**Problem.** A scheduled weekly robot audit found that a sync conflict resolution on 2026-09-15 had reverted live files to older versions.

**Observations.** 56 live scripts on the hub were smaller than their conflict copies. A further 115 conflict copies existed with no live counterpart.

Among the reverted files was the schedule watchdog, down 197 lines. Robot registry moved 466 -> 482, with 4 of the 16 new entries red on arrival.

**Instrument behaviour.** The audit tool itself produced two false readings in one run: "5 disappeared" where the true count was 0, and "40 gaps" where the true count was 30. Both were corrected by a second pass using a different method.

**Cause.** The conflict class has been known since 2026-08-11. A parcel containing the root fixes had been held in quarantine on the node for 7 days awaiting source confirmation.

**Aggravating property.** The component best placed to detect the rollback was itself among the rolled-back files.

**Pattern.** An accepted, undelivered cure is more expensive than an undiagnosed fault, because it produces belief in protection. Quarantine needs an expiry that escalates rather than an indefinite hold.

## 6. A watchdog outside its own scope

**Problem.** The census watchdog for external LLM subscription usage judges the output age of other routines and never validated its own input schedule.

**Observations.** The collector supplying it was installed on 2 nodes out of 6; green status was being maintained by manual runs. One rail showed 6 live checks and 0 sessions. After the fix, the collector stands on 4 nodes.

**Second instance, same shape.** A different watchdog counted routines from its own journal; 23 of 41 live routines were invisible to it. The test intended to catch this was reading a dead copy of the registry rather than the live one.

**Class filed.** `promise-invisible-to-watchdog`. Family `conclusion-from-a-single-surface` reached its 131st case.

**Pattern.** A watchdog that validates other components' freshness must validate its own input pipeline first, or its green is a statement about manual intervention.

## 7. Robot browser profiles holding human sessions

**Problem.** Browser profiles created for automation were found logged into the human owner's personal account across six vendors.

**Cause and effect.** One server-side session split across two local profiles is terminated wholesale by the provider, producing unexplained logouts for the human. The profile was authored for a robot tenant; the actual tenant was the human.

**Pattern.** Same shape as items 1 to 6: an artifact authored for one consumer, silently occupied by another.

## 8. Over-counted class on a remote node

**Problem.** A seed asserted three stale premises on a remote node. Two had already been cleaned before the session started. The third was real.

**Observations.** The real class: new-syntax annotations fail at runtime on an older interpreter. Grep reconnaissance projected 307 affected files; the live count was 2 of 1,438.

Two tools returned exit 2 or a TypeError on `--help`. The git channel showed 222 conflicts, 919 ahead and 4 behind.

**Cause of the over-count.** A syntax-level check passes on these files; the failure occurs at execution. Grep matched the syntax, not the execution path.

**Pattern.** A test must strike at the moment the defect executes, not at syntactic validity. A second pass by a different method caught three false readings of the first pass in succession.

## 9. Counter-example: a guarantee that is unprovable rather than unbuilt

**Problem.** The write lease guard attempted to statically derive the write set of an arbitrary shell command in order to permit safe forms.

**Result.** Proven impossible in the general case: a static parser cannot know the full write set, the process lifetime, or physical path identity after substitution for an arbitrary process.

**Decision.** Categorical deny on opaque shell forms until a separate OS-level isolation layer exists, rather than an extended syntax allow list.

**Measurements.** 10/10 opaque forms blocked, lease storm 11/11, race 1 success of 8 concurrent attempts, 0 production-attributable delta.

**Why it is the counter-example.** Every other item in this log is a boundary that was assumed and later violated by a change of consumer. This one is a boundary derived from the nature of the problem, which therefore cannot expire when the consumer changes.

## Transferable rules

1. Every rule carries an unstated assumption about its consumer. Record it as a "true while" clause at authoring time; the condition is visible then and invisible a month later.
2. A routing rule justified by "this resource is idle" must re-check that premise on a schedule. Economic facts about third parties are not versioned by the rule consuming them.
3. Bulk operations over a registry act on whatever that registry can distinguish. If the registry cannot express role, express it before the first bulk pass.
4. A watchdog's frequency derives from the consumer's deadline, not from a category. Zero token cost is an independent exemption.
5. Restate "nothing changes" invariants as "nothing changes except what these named writers own" before enabling any authorised concurrent writer.
6. A watchdog must include its own input pipeline in its scope, or its green reports manual intervention.
7. Quarantine needs an expiry that escalates. An accepted cure left unapplied produces belief in protection and is more expensive than an unknown fault.
8. Enforcement enumerated over actor names fails open on a new actor. Key on capability, or fail closed on an unknown actor.
9. Onboard a new actor adversarially. A walkthrough exercises only the paths the guard already knows.
10. Tests must strike where the defect executes. Syntactic validity is not execution.
11. When a guarantee is not derivable in principle, the correct answer is a categorical block plus a named future mechanism, not another allow-list entry.
