# Day 110 - 2026-09-21: done is a statement about a layer, not about a pipe

Dev-log form. One pattern in six instances plus one counter-example.

The unifying failure mode of the day: an instrument reports correctly on the layer it observes, the reading is then translated into a claim about the whole pipe, and the translation is performed by the operator rather than by the instrument. Every reading in this log is true. Every derived claim in this log is false.

---

## 1. Ten retrospectives, two pipes, six layers

**Problem.** Two adjacent mechanisms, a cross-machine wake doorbell and a Telegram work room transport, produced ten retrospectives in a single day. Each retrospective closed a root and declared readiness. Each subsequent live run found the next layer.

**Observations, in order of discovery.**

Layer 1, sandbox. The executor sandbox blocked the read, send and ack rails. Fixed by adding a full-access flag before resume.

Suite moved from 63 green / 40 red to 64 green / 42 red, 106 scenarios, exit 0.

Layer 2, process environment. A permanent S4U scheduler entry was installed.

First cutover failed: a task-local environment variable naming the database was not inherited by the resumed tool host. Control message `1904809` produced 0 wakes. The final addressed message `1904823` completed end to end.

Layer 3, live acknowledgement. Offline acceptance VERIFIED, live run BLOCK. The turn was interrupted before the ack.

Transport delivery and business-protocol ack are separate claims and were being reported as one.

Layer 4, stale base. The first proposed transport commit was built on an outdated base. 38 transport checks plus 6 legacy checks, all green, none of them protecting the current master consumer.

Layer 5, apply. The verified commit was never cherry-picked into live master; it sat in a separate worktree.

Live commit `d25e5098` closed this. 38/38 plus 6/6 re-run from the live checkout.

Layer 6, test isolation. Retest from live checkout plus proof the test does not mutate the production cursor or dedupe state. 44/44, production state SHA identical pre and post.

**Cause.** Each fix was correct and each completion claim was scoped to the layer just repaired, while being consumed as a claim about the pipe. No step introduced a defect; the reporting contract did.

**Pattern.** A completion claim without an explicit untested-scope line is a pipe-level assertion backed by layer-level evidence.

## 2. Elevated process returned zero before its first line

**Problem.** An install step for OpenSSH Server on a Windows node returned exit 0 immediately and wrote no log line: no error, no transcript, no start marker.

**Observation.** Zero with no output. UAC prompt appeared and was accepted by the human.

**Cause.** An elevated Windows token does not inherit mapped or substituted drives. The payload directory was on drive `E:`. The elevated process could not resolve the path it was invoked from and terminated before executing any of the script body.

**Fix.** Two edits, both portable. The script emits a start marker as its first statement and traps errors with a line number. The launcher copies itself to `C:` before elevation.

**Pattern.** Exit 0 from completed work and exit 0 from a launch that never reached the first line are byte-identical to every consumer. A process that does not announce its own start cannot be distinguished from a process that never ran. For any Windows fleet: an elevated step that "passes" while changing nothing should be checked against the drive it was invoked from before the script body is examined.

## 3. Absent signal translated into absent action

**Problem.** A physical human step was required on a peer node: click a fix script, accept UAC. A bus watcher was set to observe the evidence file. Three consecutive reports stated that the click had not happened and requested a repeat.

**Observation.** Human response: "pasted the line, pressed it - go check, fix the roots!!". The clicks had occurred all three times; the elevated script had run; the evidence file had been created.

**Cause.** Syncthing on that node was disconnected from the hub (`connected=False`). The evidence file existed locally and could not traverse to the observer.

The watcher's report ("no events") was accurate. The inference ("so he did not press it") was added by the operator.

**Aggravating fact.** A live alternate door existed for the whole window: the node's own matrix showed it reaching the anchor over ssh. The dead channel was the only one polled.

**Fix.** A single ssh entry point across the fleet was built the same day; reachable directions in the triangle went from 2/6 to 6/6. One node did not come up, and three human clicks were spent with no result.

**Pattern.** Before asserting that an actor did not perform an action, prove the instrument is capable of observing that action. Absence of signal and absence of action are distinguishable only by testing the rail, never by waiting longer.

## 4. The rollback had layers of its own

**Problem.** A new shared-folder write lease was rolled out to the fleet, blocked on live canary, and rolled back. The rollback removed 20 lease rows where 8 were owed.

**Observation.** 12 rows removed beyond scope. Post-rollback independent check on the legacy version: 14 operations OK, 10/10 under lease storm, both exit codes 0, production usage counter under the test root unmoved.

**Cause.** The undo path had no acceptance criteria of its own and no scoping assertion. It was treated as a primitive rather than as a mechanism requiring the same evidence as the forward path.

**Pattern.** "Rolled back" is the same class of claim as "fixed" and needs the same layer disclosure. A repair mechanism that leaves residue is a repair mechanism without a test.

## 5. The gate was not the blocker

**Problem.** 121 follow-up drafts written and never sent, carried forward from Day 109 as an open fork. The apparent cause was a human-approval gate.

**Observation on removing the gate.** The approval was not being withheld for policy or workload reasons. It was being withheld because the generator produced text the human was not willing to send under his own name.

**Cause.** The visible blocking step was downstream of the actual defect. Removing it without repairing the generator would have automated the defective output at higher throughput.

**Fix.** Seven roots repaired in one pass: event filter, text generator, daemon crash loop, CRM card linkage, reminders. Measured: 748 meetings, links 244 -> 348, daemon crashes 29/day -> 0, 301 overdue items cleared. The 121 historical drafts remain marked stale by design, having been produced by the broken generator.

**Pattern.** A gate that is never passed is evidence about the artifact behind it, not only about the gate. Before removing an unused approval step, inspect what it has been suppressing.

## 6. Parallel duplication invisible to recall

**Problem.** One voice task was claimed independently by three sessions. All three produced the same PyTorch podcast: three notebooks, three audio files. A fourth attempt exhausted the daily vendor quota.

**Observation.** Defect class was created at 9 cases dating to 2026-08-13, because it was counted by defect family rather than by instance name.

**Cause.** Recall queries persisted state. Concurrent in-flight work by sibling sessions is not persisted at claim time, so a recall immediately before an irreversible step returns clean.

**Status.** Root named, no mechanism yet. A cheap pre-irreversible-step concurrency probe is not wired into the pipeline.

**Pattern.** Recall over committed state answers "has this been done" and cannot answer "is this being done". The second question needs a claim registry, not a search.

## 7. Channel watchdog covering one modality

**Problem.** The primary task intake rail processed voice notes only. Text, images and file attachments were accepted by the channel and never dispatched.

**Observation.** 151 messages reviewed, 16 forgotten tasks recovered, 40 duplicates prevented by the new second door.

**Adjacent loss, same rail.** A voice note about an urgent call was lost when an HTTP timeout tore the session. Of 30 messages, 19 obtained a session and 11 did not. One remote duplicate session cost 5.48 USD.

**Cause.** The watchdog was built around the format the rail started with rather than the channel boundary.

**Pattern.** A watchdog scoped to a format silently excludes every other format the channel accepts. Scope watchdogs to the channel, then enumerate modalities.

## 8. False bottom in a paginated collector

**Problem.** A message lane collector treated a short result page as the end of the feed.

**Observation.** Corrected run moved the lane from 36,944 to 174,481 messages. Roughly 80% of history would have been silently omitted.

**Second observation, unrelated to correctness.** Six days after the lane was built it had served two searches.

**Pattern.** "Returned little" and "reached the end" are different facts and require different assertions. Separately: a pipe with a full index and no reader is a build, not a delivery.

## 9. Help flag executed live work

**Problem.** `vault_backup.py --help` performed a live vault snapshot instead of printing usage.

**Cause.** Argument parsing fell through to the default action for unrecognised flags.

**Pattern.** `--help` is the cheapest reconnaissance move available and is relied on by the "ask the tool before declaring impossible" rule. A tool whose help flag performs work poisons the discovery step that every other rule depends on.

## 10. Counter-example: rollout stopped on a proof, not on a failure

**Problem.** The task-claim mechanism lacks an epoch and a fencing token. A fix was built and accepted.

**Observation.** Provider acceptance 96/96. Common-door enforcement 0/9. Live rollout status: BLOCKED.

**Reason for the block.** A rolling upgrade of two dependent sides admits an ABA counter-example in which the stale side overwrites the fresh claim. The block was declared from the counter-example, not from a failing test.

**Why it is the counter-example of the day.** Every other item in this log converted a green reading into a shipping decision. This one refused to ship against a green reading because the remaining risk was proven rather than observed.

## Transferable rules

1. A completion claim must carry its scope: which layer was verified and which layer was not touched. Without the second half it is a pipe-level assertion on layer-level evidence.
2. Any process that can fail before its first statement must emit a start marker as its first statement. Otherwise exit 0 is ambiguous between success and non-execution.
3. On Windows, elevated tokens do not see mapped or substituted drives. Copy the payload to a local fixed drive before elevating.
4. Before reporting that a human or peer did not act, verify the observation rail is live. Absence of signal is evidence about the rail until proven otherwise.
5. An environment variable set on a task is a process property, not a contract between process owners. Cross-owner configuration needs an explicit handoff.
6. Rollback paths require acceptance criteria and scoping assertions identical to forward paths.
7. An approval step that is never exercised is evidence about the artifact behind it. Inspect the artifact before removing the step.
8. Recall over committed state cannot detect concurrent in-flight work. Irreversible steps need a claim registry, not a search.
9. Watchdogs are scoped to channels, not to the modality the channel started with.
10. Pagination collectors must distinguish "few results" from "end of data" by an explicit terminator.
11. A green acceptance suite does not authorise a rolling upgrade of two dependent sides. Prove the absence of a stale-overwrite counter-example first.
