# Day 100 - 2026-09-11: you are billed for having it, and paid only for what arrives

Source: four full retrospectives plus twelve abandoned-session reviews across two nodes. No canon beats exist for this date; the last beat is dated September tenth.

**Edge of the day.** Cost is charged for presence, value is delivered on arrival, and the two had never been measured apart. The skill shelf bills every session for the full set of descriptions while roughly a third of those descriptions never reach the model in usable form.

**Mirror finding of the same day.** A capability we owned was recorded in our own canon as nonexistent, and the recheck cost one free command. We were paying for undelivered capacity and abstaining from delivered capacity at the same time.

## Incidents

### 1. The skill shelf is a standing per-session tax

Measurement: 189 own skills, 147,725 characters of descriptions, 42,207 tokens loaded per session. Node session volume that day: 694.

The figure is independent of usage. Zero calls and twenty calls cost the same.

Decision (delegated by Anton, "you decide, co-founder"): trim prose and procedure from descriptions. Contract: at most 400 characters, one line, quoted.

Projected saving after normalisation: 19,601 tokens per session.

### 2. A triggers field with no proven reader

Five skills on the shelf carry a separate `triggers:` field. All five arrived from foreign packs.

No evidence exists that the harness reads that field. Moving keywords into it would delete them from the delivery path while appearing to save space.

Rule as written: triggers remain inside the description; the field stays unused until reading is proven.

### 3. Sixty-eight descriptions are replaced by a heading from the body

A five-skill canary broke a YAML parse on an unquoted colon. Fixing it exposed a root worth more than the intended saving.

An unquoted description is in places not parsed; the harness then displays a heading from the body of the file in its place. Trigger words never reach the model at all.

Shelf recount: 43 descriptions quoted, 146 unquoted, 68 of those folded blocks with guaranteed substitution.

Consequence: about a third of the shelf has no automatic pickup and works only on an explicit call by name, while being billed in full every session.

Bulk edit registered as a finite routine (184 items, quota 10 per run, ETA 19 days) and deliberately **not launched** pending the canary harvest on September eighteenth. Canary conversion: 5 of 5.

### 4. A canon line said a capability did not exist, and one free command refuted it

The canon mirror stated that the second agent has no native skill shelf. A single zero-token command showed a native shelf exists and had existed for months.

Class: `stale-claim-in-canon-blocks-capability`, first dated occurrence. The prohibition was recorded as a fact and carried no recheck date.

Bridge built the same pass: 234 skills mounted by junction from one source, zero copies. Engine exposes `status|sync|gaps`, nightly caller wired into housekeeping, acceptance in two layers where the second layer queries the agent rather than the script.

Delivery measurement on the far side: about 25 of 706 description characters arrive, roughly four percent. Name visible, triggers not.

### 5. A second shelf of copies was frozen in June and no watchdog saw it

The second acceptance layer found a second skill root holding 55 copies frozen on June twenty-sixth. The agent treated it as an equal discovery root and could load a June procedure instead of the current one.

Duration of the drift: two and a half months, invisible to every watchdog.

Same-day refutation: another session measured the same folder and found 236 ordinary copies, 161 differing from source. The conclusion "the copies are gone" went stale within hours; the cause of their return is unproven.

### 6. A home file had a live consumer nobody had looked for

A separate rulebook from June twenty-sixth (121,653 bytes) sat in the home folder and nearly doubled the startup prompt.

Initial verdict: archive it. That verdict was wrong. 

A background link check found a live consumer: a third CLI tool has no per-folder documents and reads only the global home rulebook. It had been answering by June canon for two and a half months while the mirror watchdog printed `ok`, because the watchdog guarded a different house.

Fix: publication now writes one versioned digest into both homes. Home prompt dropped 146,906 to 105,828 characters, gates 5/5, lint ok, engine selftest 14/14.

Class: `canon-mirror-second-home-unguarded`, first dated, repaired in the same pass. Family: derived copies drifting faster than the refold that produced them.

### 7. A counter lied three ways and all three favoured us

Trigger: the counter reported a skill call that the harness had rejected the previous day, and reported two calls where there was one.

Three independent defects in the fleet's shared instrument:

1. The transcript scanner stamped `outcome: ok` on every event without reading the call result, so rejected calls counted as successes.
2. Hook and scanner wrote the same event under different id schemes, so deduplication never collapsed the twins.
3. Hook signed the node with a fleet key while the scanner used an `origin:*` label, so one machine appeared as two rows.

Measurement after repair: 676 calls over 14 days became 479, minus 29 percent. The most-used procedure went from 215 to 138.

Direction is evidence: all three defects inflated, none deflated.

Rolled out as a parcel to six nodes.

### 8. A red control went red for the wrong reason

The first version of the red-first control for incident 7 reddened because the test copy was laid out differently from what the test expects, not because of the injected defect.

Second version compares against a clean-copy baseline. Fourteen cases, three of them red on sabotage.

Rule: a red control that has not been compared against a clean baseline proves nothing.

### 9. A background wrapper returned zero while the engine died of memory

Overnight index build: 2,093 files into 70,113 chunks, 20,835 symbols, 144,551 edges, 11h55m on CPU. Smoke query returned the correct file at 0.86 relevance.

The smoke run also exposed two corpus defects: sync-conflict duplicates occupying the top results, and an entire scripts folder missing from the corpus.

First repair produced a false green: the copy command carried a literal instead of a variable, stderr was redirected to nowhere, and the report claimed 1,226 files added. Actual: zero.

Caught by the next incremental reindex printing "0 changed". Redone with verification: 245 files added, leak scan clean.

Class: `silent-stderr-swallow-fake-green`, first dated occurrence, then a second the same day: a background wrapper returned exit 0 while the native binary died of memory exhaustion at 2,000 of 5,240 files. Truth existed only in the tail of the log.

Family refinement recorded: background launch plus redirect to file means the wrapper exit code carries no information, and the log tail must be read before reporting.

### 10. An on-air board is a lamp and not a lock

Question from Anton: is it dangerous for two different agents to work in the same folder.

Read by implementation rather than by description: `declare` writes the claim, then reports the intersection, and still returns a success code. The model knows 13 broad zones and cannot distinguish questions inside a zone. Board state at the time: 0 active, 1,240 archived.

An atomic mechanism already existed and was idle: a claim keyed on a stable question id, where `O_EXCL` yields exactly one winner per machine. Across machines over file sync it remains advisory.

Decision: build no new dispatcher. Three layers from existing parts, a question claim, a zone signal, and a worktree plus file lease for code writes. One implementer writes; reviewers read or work in separate worktrees.

Withdrawn advice: an earlier suggestion to lean on another internal bus was retracted after checking; its database had been dead since July fifth and its claim is not atomic.

Class: `verdict-before-consumer-search`, at least six prior occurrences by family; the dedicated repair session is overdue.

### 11. A gate blind to its own claim

A hook rejected an edit to a zone while the same session held an active collaborative claim on that zone. Editing the same file through the ordinary editor path passed.

Class: `onair-guard-blind-to-own-claim`, first dated occurrence, recorded, no mechanism built.

### 12. An own door was built because the borrowed ones were blocked

Foreign OSINT packs for people search are blocked for us and were not worked around. A dedicated door was built over our own corpus and run immediately on a live task.

Result: decisive negative. No matches for the target handle across dialogues, groups, participant exports, or any spelling of the name.

An honest zero is a usable answer; the search moves to a surface where the person is known to exist.

### 13. A snapshot robot hijacked authorship

The auto-snapshot robot pulled 46 foreign skills into our repository in three minutes.

Class at eleven dated occurrences against a threshold of three. Repair session queued.

### 14. Two rules accepted, each with an executable door

Rule one: a skill with no named and notified consumer does not exist. Door: a description audit that exits non-zero until a `consumer:` field, quoting, and the 400-character limit are satisfied.

Rule two: a skill is written on the assumption that another agent will call it. Door already existed: a report naming which skills depend on an interface only one agent can reach, 32 of 236.

Both written into the canon the same day despite the canon sitting in the yellow size zone. Writing a rule is never gated by size.

## Reusable rules from this day

1. **Measure presence and delivery separately.** A catalogue priced by item count says nothing about how much of it reaches the consumer in usable form.
2. **Form is delivery.** The only proven description form is a quoted single line; an unquoted one may be silently replaced by a heading from the body.
3. **Never migrate content into a field whose reader is unproven.** The saving is immediate and the loss is invisible.
4. **A prohibition recorded as fact needs a recheck date.** A negative claim creates no work, so nothing forces it to be revisited; ours cost months of an unused capability.
5. **Ask which house the watchdog guards, not whether one exists.** A second home of the same source can serve a foreign consumer with stale content indefinitely.
6. **When an instrument's errors all point the same way, the direction is evidence.** Three independent defects that all inflate are a flattering instrument, not a noisy one.
7. **A red control must be compared against a clean baseline.** Otherwise it reddens for its own layout and certifies nothing.
8. **A background launch invalidates the wrapper exit code.** Read the tail of the log before reporting.
9. **Do not build a dispatcher when an atomic claim already exists.** Visibility, claim and lease are three separate layers, and only one of them is a lock.
