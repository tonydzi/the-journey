# Day 101 - 2026-09-12: red that nobody reads is indistinguishable from green

Source: three independent abandoned-session reviews on three nodes, run in reduced profile. No canon beats exist for this date; the last beat is dated September tenth. That gap is named, not skipped.

**Edge of the day.** A routine requires three independent wires to do work: a schedule that fires, a task that arrives non-empty, and a reader who consumes the verdict. Each wire fails silently, and all three failures present identically from outside: no output plus a green health stamp.

**Corollary.** A red signal with no reader is operationally identical to a green one. Truth of the signal is irrelevant until something consumes it on a schedule.

## Incidents

### 1. Nine nightly routines missed their schedule on a laptop that sleeps

Symptom: one node stopped emitting daily plan files after September ninth, while peer nodes emitted on the tenth, eleventh and twelfth.

Evidence: scheduler operational log, event 153, verbatim: `did not launch task "inbox-robot-am" as it missed its schedule`. Prior task result code `0x800710E0` had been interpreted by an older card as a possible operator decline; that card was guessing because the operational log was disabled at the time.

Scope: nine live daily routines carry `StartWhenAvailable=False` and are all currently in missed-schedule state (canon optimizer, CRM nightly refresh, dev map, inbox robot AM, inbox robot PM, orphan engines daily, archive nightly delta, token audit, token audit sheet daily).

Root: canon mandates a 23:00-06:00 execution window; the node is a laptop and is powered off at night. The rule is correct for always-on nodes and silently wrong for this class.

Repair: set `StartWhenAvailable=true` across the nine tasks. Reversible, no admin rights. The run attempted it and was blocked by the autonomy-mode classifier; no workaround was attempted, command and acceptance criterion parked in a card.

Impact: since September ninth the inbox robot must execute signed tier-one parcels rather than plan them, making it the debt payer for this node. Node currently shows eleven unexecuted orders (oldest 49 days) and three unopened parcels on every session start.

### 2. A janitor woke, greeted nobody, and exited zero in six seconds

Cron fires at 03:00:00; health stamp written at 03:00:06 with `{"exit":0,"ok":true}`. Heartbeat file for the same routine has not been updated since September tenth.

Two watchdogs observe the same run and disagree. Nothing compares them.

Root: not proven. The prompt reached the model empty on those two nights; why the file substitution returned an empty string is not closed by evidence. Reviewer operated in a reduced profile and did not repair beyond boundaries.

Class journaled: `silent-green-watchdog`, line 17. An assigned repair session has been `queued` since August twenty-second and has never executed.

### 3. An ACL mask flipped back, and the time of repair was recorded

The mask recurrence was live at 05:26 (`user:anton:rwx` collapsing to `#effective:r-x`, write test negative). It was repaired at 05:28, non-recursively.

The repair time was written into the report deliberately. A later measurement will observe a healthy mask and may conclude the emitter has calmed down; that conclusion would be false and convenient. A run on September fourth deliberately left the mask broken to preserve the evidence; today the mask blocked the mandatory pre-write backup, so a timestamp replaced the preserved evidence.

Rule: a repair that destroys evidence must leave a dated record in its place.

### 5. My own counter inflated orphans six-fold against the watchdog

The reviewer first counted orphans itself, by regex over memory files against the index and archive, and got 498 of 1001. The watchdog door gives 73.

The material point is not the arithmetic. 498 supports the conclusion "this node's memory collapsed"; 73 supports "the watchdog lost its schedule". The inflated number backed the more dramatic claim, and the reviewer was reading the skill's warning about crooked instruments in the same run.

Rule reaffirmed: when your instrument disagrees with a purpose-built one, and yours favours the more dramatic conclusion, publish the purpose-built number.

## Reusable rules from this day

1. **Instrument the three wires separately.** Schedule fired, task non-empty, verdict consumed. A health stamp that only proves process exit covers one wire of three.
2. **Red with no reader equals green.** Before trusting any watchdog, name the scheduled consumer of its verdict. No consumer means no signal, regardless of colour.
3. **A rule written for one machine class must name the class.** A night window is correct for always-on nodes and silently wrong for laptops; nine simultaneous failures are one rule defect, not nine incidents.
4. **Turn the log on before interpreting a return code.** An enabled scheduler log converted a two-week guess into a one-line fact in a single query.
5. **A repair that destroys evidence leaves a timestamp in its place.** Otherwise the next measurement reads the healed state as calm and publishes a convenient falsehood.
6. **When your instrument disagrees with a purpose-built one and yours is more dramatic, publish theirs.** Six-fold inflation backed the conclusion "memory collapsed" against the true "the watchdog lost its schedule".
7. **Match project and touched files, not just the hint, before batching sessions.** A repeated human ritual is a third false-batch signature and the most convincing one.
8. **A file without an index line exists only for whoever knows the path.** Throughput from finding to table of contents measured today: one in eight.
9. **A queue without an automatic consumer may be a decision.** Verify against the registry and the producing instrument before calling it a hole, and read the full output before writing the verdict.
