## 0. Contract

## 1. Vault backup: dead, not frequent

Problem: order "no point backing up the vault 5 times a day". Voice note missed the session (inject hook used another machine's user path; fixed by Codex by 11:14).

Cause: abandoned `.git/index.lock` (0 B, 11-02 11:01) blocked git snapshots 4 days; cloud re-uploaded the same 6.41 GB delta nightly. Schedule 28-32/day, actual 0.

Class `stale-git-index-lock` case 3 (10-27, 10-29, 11-06). Test T11s (10-29) required lock moving; code absent.

Solution: move lock > 30 min, re-check inside own lock; T11s, T22 green, red on old. Throttle 168 h, `--now` forces. Cloud on Sundays.

Retention: keep=14 promised, deletion disabled, warning in unread log → keep week + month copy. Tests 9/9 and 5/5, red on 3 sabotages each. Laptop free 83.3 → 347.3 GB, hub +293 GB, 421 GB to cloud trash.

Moved pain: new output token `THROTTLED`. Hub nightly podcast job parses output by regex (`committed|NO_CHANGES`); producer in synced folder, reader in unsynced scripts folder → would fail "did not confirm HEAD".

Fixed remotely; old copy fails on probe. Side: edit tool converted `.cmd` CRLF → LF; restored.

Open: Macs unapplied; hub second copy rc=2 / rc=267014; two machines prune the same cloud; age-only lock moving. Panel 6/6, then 3/6.

## 2. Hub: dispatcher fix slowed the prompt

Problem: hub lag; cursor lag over AnyDesk 00:45 UTC.

Cause A: Syncthing uplink 6.8 MB/s. Solution: cap 1500/3000 KB/s → 1.6 MB/s; operator "Yes, it's alive". Latency not instrument-measured.

Cause B: dispatcher log 2121 calls, Bash p50 96 ms, prompt p50 1.9 s / p90 14 s / max 68 s. In-process guards sequential, no timeout; Windows subprocess timeout waited on grandchildren pipes (199 s).

Solution v3: temp files, wait guards only, `taskkill /T`, keep exited guard refusal. Red/green: 27 s → 0.6-3.2 s; Bash p50 23 ms, p90 233 ms (n=1262). Memory hook cache 12.9 → 1.9 s, parity on 5 nodes.

Moved pain: after isolating `clone_gate`, prompt p50 6.8 s, p90 21 s, 109 × 20 s timeouts overnight. Marker "session checked" written after the long search; killed gate never wrote it, re-searched every prompt.

Caught by retro panel 6/6, not by author. Fix: claim + marker before search; `os.scandir` 14942 files 3.2 s (was 8.4); first prompt 1.1 s, repeat 85 ms.

Moved pain 2: 23 tasks to 00-05 UTC table; night 1: 14 OK, 5 failed (all pre-existing), 2 weekly off-schedule; two overran to 05:09 and 06:04; operator worked inside the window.

Open: session start p50 6.6 s; in-process PreToolUse guards without timeout; grandchild leak; Mac dispatcher not installed.

## 6. Patterns

P1. A fix is accepted after neighbours are measured, not the treated spot.

P2. Changing a shared producer's output requires finding readers on every node; synced producer + unsynced reader = version skew.

P3. A test without the code it tests is not a fix; check the test was red on old code.

P4. Marker/claim before long work; a killed worker must not repeat it forever.

P5. Remeasure all hook events after dispatcher changes, not the one you optimized.

P6. A favourable ranking on n=24 waits for a larger set.

P7. Linking a whole directory widens the blast radius of foreign delete commands.
