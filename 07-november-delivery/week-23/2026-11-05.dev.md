## 0. Contract

## 1. Hub console flashes

Problem: a black console window every few seconds on the hub, stealing input focus.

Diagnosis: 90 s poll (`psutil` + `EnumWindows`/`GetForegroundWindow`) named `codex_rewake.py __run`, the Codex session alarm.

Cause A (window): DETACHED runner spawned `codex.exe --version / debug models / exec resume` without CREATE_NO_WINDOW; each child got a Windows Terminal window.

Cause B (rate): `finally` saw the runner's own unread letter in pending and spawned a new runner. Counters for 11-05 pre-fix: `respawn-late-pending` 2833, `no-turn-started` 2830, `turn-entered` 7.

Solution: `failed` flag, respawn only on new letters; CREATE_NO_WINDOW on children.

4 more sources and 3 scheduled tasks fixed (`run_hidden_wait.vbs`, `pythonw`). Test 20/20, 2 FAIL on old code. Window count: dozens per 60 s before, 0 from the alarm in 3 min after.

Rejected: global window hider. It removes evidence and leaves the loop.

Gotcha: `conhost --headless` from Task Scheduler does not hide (Windows Terminal intercepts); works only from a GUI parent.

Side: event journal `console_flash_log.py`, 4/4; Codex blocked twice for raw argv and window titles; now exe/pid/ppid/basename only.

Open: parcel to 9 nodes, 8 not applied. No lint for the class; third dated case. Pre-anonymisation log rows remain locally, owner decides.

## 5. Patterns

P1. A trigger authored by the actor itself is not work.

P2. Fix the emitter; a hider deletes evidence and keeps the cost.

P3. Child processes of consoleless parents need CREATE_NO_WINDOW.

P5. Judges and tests must see the same text the decision depends on.

P6. Recovery batch size must not recreate the failure condition.
