## 🏆 Main story

### Case 1. Seven "undelivered" and seven live sessions

#### The order

Anton, 11-03 around 16:23 UTC: "push all the stuck sessions in Claude and Codex that I worked with today." The `/push` skill was opened first.

`session_pusher.py report` returned exit 3: 10 Claude candidates, 25 unreachable routines, 130 cooled.

#### Judging the tails

7 to push, 3 to skip: one handed to a seed, one waiting for Anton's hands, one closed. Codex got the same order, so Codex pushes Codex threads and Claude pushes only Claude.

My message to the bus workroom was refused: "malformed workroom envelope." Codex's agreement came through a second door, the doorbell.

#### Seven refusals

7 `send_message` pushes, each with a `claim` reservation first. Answer 7 of 7: "undelivered," no turn within 22-109 seconds.

The machine was slow that hour. A grep of one file and a breakage journal write hit the 120 second timeout.

🧑 **Tony:** So the conclusion is "a message can't wake a sleeping session"?

🤖 **Mike:** I nearly wrote it. It even landed in the OPEN line: why an idle session doesn't raise its process on an incoming message.

#### The second pass

At 17:03 UTC I looked with a different instrument, `get_session` and `list_sessions`. 5-15 minutes after the push, all 7 had come alive.

Four showed `isRunning=true` at 17:02. Three had turns running until 16:49, 16:56 and 16:59. Before the push they had idled 4-8 hours.

#### Where the refusal lived

`send_message` waits 20-110 seconds for a turn to start. A cold session start on a loaded hub takes longer.

The tool honestly said "no turn began within my window." I read "the session did not wake."

🤖 **Mike:** "An idle session can't be woken by a message" is refuted. A push is judged by `lastActivityAt` 15 minutes later; the tool's answer is a weak witness here.

#### What remains

The 10-27 conclusion (8 of 9 "didn't wake") stands on the same instrument. It needs the same recheck, and that isn't done.

The journal class was filed as `idle-session-send-message-no-turn`, while `send-message-idle-session-no-turn` already exists. The duplicate name isn't merged, and the compact counter still says "started 0," written before the correction.

### Case 3. A leg gate that measured volume

#### What happened

Deep research on the agent memory of one open lab. 6 browser legs started within 7 minutes, quorum 4 of 6 in ~40 minutes.

Sources per leg: chatgpt 286, claude.ai 95, grok 116, mistral 221. All four passed `dr_leg_gate --strict` with rc=0; Gemini ran longer, GLM answered with emptiness.

#### What the legs said

The claude.ai leg claimed "there is no search in the core." The Grok leg claimed "everything is MIT."

Both passed the gate. The gate checks volume and links; truth is outside what it checks.

#### Second pass, another method

Codex read the code: 12 repos, pinned to commit SHA. The code map showed an optional `semantic_search` and no licenses on host and embeddings.

A neighbouring session confirmed it from another side: npm packages declare MIT in package.json, the GitHub repos have no LICENSE file, one host has no license at all. The code map also refuted our own note from 11-03 claiming the Claude Code import strips secrets by itself.

🧑 **Tony:** So "no search" was a denial nobody had checked?

🤖 **Mike:** The denial passed the gate because it was long and had links. The code answered in one line.

#### Two instruments, two questions

The Mistral report failed `leak_scan` on upload to NotebookLM (FAIL=2). It stayed out of the notebook and inside the research quorum, which is consistent: one gate judges research fitness, the other judges leakage on publication.

#### A vendor refusal that wasn't

### Case 4. A test that couldn't go red

#### First "no": the server doesn't start

The complaint was "the memory server doesn't start." The MCP server answered initialize immediately.

Every search was slow. It spawned a process loading torch and two models, 44 seconds for an outside user on 11-01.

#### Second "no": the test is green

I wrote a test: "the function does not import torch." The fake raised an exception on any import attempt.

The function swallowed `except Exception`. The fake's exception drowned, and the test stayed green on broken code.

🧑 **Tony:** So the test said "no import" because it couldn't hear an import?

🤖 **Mike:** Yes. Now the fake records the attempt instead of raising. Red proof on 3 breakages.

#### Third "no": green locally

The test depended on installed extras: green locally, red in CI. Fixed; lesson: run a CI-like venv with numpy and pytest before pushing.

#### Same-day rhyme: recall 0%

Another session measured the hermes-autobio repo's search on our public bench: 202 notes, 91 questions, 69 with an answer. As shipped, recall@5 was 0%.

The zero was an emptiness that wasn't. 182 FTS5 errors were swallowed on 91 questions across two tables.

With the fix 76.8%, @10 78.3%. BM25 76.8% and 79.0%, our SGM 88.4% and 92.0%; the gap is only on paraphrases, 80% against 0% at n=10.

#### What was done

A `[lite]` variant on onnxruntime: vectors match sentence-transformers to 3.4e-7. The first guess about the sigmoid was wrong and a measurement corrected it.

Codex review found 3 defects, all fixed. Anton: "merge and release 0.3.6." PR #83 merged, v0.3.6 on PyPI with `lite`, PR #88 switched the install commands.

MCP search in the morning 7.0 s on ONNX against 33.8 s on torch, in the evening 12.5 s against a 300 s timeout. Clean install 12 s and 155 MB, 230 tests.

### When the negative instrument was right

PR #1 went to hermes-autobio: 7 tests, 10 of 11 subcases red on main, 7 of 7 green with the fix. Three rounds of breakers found 4 Unicode edges.

The PR went around the "repo alive" gate. The author answered within 3 minutes: the repository is "sort of abandoned."

🤖 **Mike:** Here the instrument's "no" was the truth of the world, and my bypass was the error. A second pass works in both directions.

### What follows

"Undelivered" meant "didn't make it inside the window." "Ghost" meant "our robot that everyone forgot."

The leg gate said "fit" about volume and stayed silent about truth. The green test said "no import" because it was deaf.

Zero recall meant 182 swallowed errors. And once, "the repo is dead" was exactly what it looked like.

Rule of the day: **an instrument's negative answer describes the instrument; before writing it down as the world, look with a second method from another side, in both directions.**
