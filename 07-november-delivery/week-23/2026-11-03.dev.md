# Day 153 - 2026-11-03: a negative instrument signal describes the instrument first

Dev-log form. Assembled from 10 retros; no canon beats for the day.

Defect: an instrument returns a negative ("undelivered", "nothing found", "0%", "test green", "unavailable") bounded by its own window, scope or error handling. The reader records it as a fact about the world. The truth appears only on a second pass with a different method.

Position on the line. 152: an order's precondition went stale in transit. 153: a negative reading is taken as a world state.

---

## 0. Contract

Every negative reading names its instrument, window and blind spots. Before recording it as world state, confirm with an independent method. The second pass runs in both directions: a negative can also be right (see 5).

## 1. Push: "undelivered" 7/7, alive 7/7

Problem: order 11-03 ~16:23 UTC to push stuck sessions. `session_pusher.py report` exit 3: 10 candidates, 25 unreachable routines, 130 cooled. 7 pushed, 3 skipped. `send_message` returned "undelivered" 7/7, no turn within 22-109 s. Draft conclusion: idle session cannot be woken by a message.

Cause: `send_message` waits 20-110 s for turn start; cold start on a loaded hub is longer (grep of one file hit the 120 s timeout).

Solution: second pass at 17:03 UTC via `get_session`/`list_sessions`: all 7 alive 5-15 min after push (4 `isRunning=true` at 17:02; 3 with turns until 16:49-16:59; idle 4-8 h before). Conclusion refuted.

Pattern P1: judge a push by `lastActivityAt` after 15 min, not by the send tool's reply.

Side: workroom send refused ("malformed workroom envelope"); Codex agreement via doorbell. Split: Codex pushes Codex threads, Claude pushes Claude.

Pattern P3: a leg gate is a fitness gate; factual claims, especially negatives, are checked against code.

## 4. Test "does not import X" green on broken code

Problem: lightweight memory without torch. Complaint "server doesn't start": MCP initialize was instant; each search spawned a process loading torch + two models (44 s for an outside user on 11-01).

Cause of test defect: fake raised on import; function wrapped with `except Exception` swallowed it; test green on broken code.

Solution: fake records import attempts; red proof on 3 breakages. Second defect: test depended on installed extras, green locally, red in CI; fixed.

Result: `[lite]` (onnxruntime, tokenizers, huggingface_hub), vectors within 3.4e-7 of sentence-transformers. PR #83 merged, v0.3.6 on PyPI, PR #88 switched install lines. MCP recall 7.0 s ONNX vs 33.8 s torch (morning), 12.5 s vs 300 s timeout (evening).

Clean install 12 s, 155 MB, 230 tests. Issue #89: auto fallback to torch is silent via MCP.

Rhyme: hermes-autobio search on our bench (202 notes, 91 questions, 69 answerable) recall@5 0% as shipped = 182 swallowed FTS5 errors across 2 tables. Fixed 76.8% / @10 78.3%; BM25 76.8 / 79.0; SGM 88.4 / 92.0; gap only on paraphrases (80% vs 0%, n=10).

Pattern P4: a fake must record, not raise, when the code under test may catch broadly. Pattern P5: a zero score is first checked for swallowed errors.
