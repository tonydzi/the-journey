## 1. Public dataset push

### 1.1 Context

Task: decentralise live session transcripts across all owner nodes (mesh instead of star). Done: 6x6 mesh, separate history folder, 7-day bin on all receivers, `st_sessions_live.py` fleet-status and fleet-lag (43 tests, mutants red). Mesh 42/42 cells = configuration; delivery proven only by fleet-lag, 18/30 OK at retro time.

### 1.2 Problem -> Cause

| Item | Fact |
|---|---|
| Dataset `.gitignore` | `*.jsonl` since 08.10 |
| Effect | HF dropped all raw files silently |
| Push verdict | "OK" by sha of the commit |
| Commits | 72 empty |

### 1.3 The order error

Action: ignore line removed, push started immediately. The ignore line had been acting as an accidental lock. The push published raw session files with unmasked personal fields; the mask audit (two methods + full store scan) ran after.

Audit: keys and passwords masked; a set of personal-field classes not masked.

Response: push killed; all publishing tasks disabled; neighbouring publishers warned. Mask fix not started: executor agent stopped by model safeguards. Checker confirmed mask unchanged, traps still pass.

Closing the dataset and cleaning its history = owner decision. Outward post for the day skipped (would draw attention).

### 1.4 Solution (gate)

| Gate | Behaviour |
|---|---|
| Pre-check | `cmd_push` inspects `.gitignore` before upload |
| Post-check | "HF accepted N of M"; success only by re-read remote file list, never by commit sha |
| New data shape | full detector scan of the store before first push |
| Mask gate | tested with traps of several classes, not one sample |

Panel (6/6) accepted: order of events (the remote raw folder did not exist before this run); mesh config vs delivery are separate claims; count-based checks do not see content corruption (accepted as limit).

## 8. Patterns

P1. An obstacle that blocks data flow may be an accidental lock. Before removing it, scan what it holds with the same detector the publish gate will use.

P2. "Published" = re-read remote file list matches what was sent. A commit sha, an exit code or "push OK" proves nothing about content on the remote.

P3. Acceptance = the consumer's answer (model step, transcript line, remote listing). Start events and process status are knocks.

P4. An error string is a symptom. `Operation not permitted` was an orphan server, not a missing permission; read state (versions, socket owner, settings) before concluding.

P5. "Cannot" is a claim. RECALL fleet memory before saying it.

P6. A copy of a WAL database without its journal looks stale while the data is fresh.

P7. A discarded inconvenient run hides the variance. Re-measure; never exclude post hoc.

P8. Reaper patterns must be tested against live `ps` output, including full paths.
