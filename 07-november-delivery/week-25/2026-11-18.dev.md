## 9. Patterns

P1. Before building a door, enumerate existing doors for the same resource (registries, gates, queues, hooks). A new door ships only together with removal or delegation of the old one.

P2. If the platform or a standard already exposes the control (Scheduler interval, trigger EndBoundary, `delete_branch_on_merge`), use it; code that re-implements it is a second schedule.

P3. A shared registry with caps is the door. Any publisher that does not call it before and after release bypasses the cap.

P4. Moving data under a watchdog without updating the watchdog's layout makes it blind and green. Declare the layout once and import it.

P5. A diff panel judges only the diff; a missing call to an existing gate is invisible to it.

P6. Judge "merged" by identity (tip sha == merged PR head, base == default), never by a derived counter.

P7. A mirror verified against its local source stays green on a stale source; verify against the fleet version.

P8. Compare variants only within one pass of the same judges; cross-day runs are artifacts.

P9. A long process started from ssh dies with ssh; run it as a Scheduler task.
