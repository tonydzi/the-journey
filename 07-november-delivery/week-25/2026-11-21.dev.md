Defect: one exit code (or one signal) covers two distinct events. The reader of the code picks one meaning, usually the worse one: a live process is called dead, and a real alarm can drown among false ones. ## 8. Patterns

P1. One exit code = one event. A watchdog with overlapping codes (finding vs crash, grey vs dead) poisons every downstream reader.

P2. The healer must read the code map wherever it is. A fixed read window (first 80 lines) silently turns a documented code into an unknown one; a shared `expected_exit_codes.json` removes the window.

P3. A crash must not write partial results that a later reader can mistake for findings.

P4. "Dead task" needs two readings before a verdict: exit code and Scheduler events (201, 329). A kill by time limit is not a task failure.

P5. Two numbers that must fit together (task limit, build duration) live in one place and are computed, not edited separately.

P6. Re-reading an unchanged input is waste; cache by content hash.

P7. "Witness did not see the write" has two causes: witness dead, or write bypassed it. Find the writer before declaring the witness dead.

P8. An outcome judge distinguishes tool status from returned data text; test it on real responses in both directions.

P9. Token boundaries must treat escape sequences (`\uXXXX`, `%XX`) as boundaries; a scrubber rule change needs a cache bridge.

P10. Red proof on old copies runs with outward doors disabled; otherwise the test is a live caller.

P11. A live source (name on disk) beats a passed argument.
