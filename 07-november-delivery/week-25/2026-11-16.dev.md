## 9. Patterns

P1. A guard on an invocation path closes that path only. Lock the resource (folder stub, file mode, permission) when the consumer set is open.

P2. A door is closed after a live shot from each consumer, not after reading config, `--help` or a green instrument.

P3. An instrument that verifies "written" must be paired with one that verifies "read" by the actual consumer (`~/.grok/` vs `~/AGENTS.md`).

P4. A verifier that shares the fixer's planner inherits the fixer's blind spots; enumerate consumers independently.

P5. Timeout and dry-run are "unknown", never "0" or "applied".

P6. Whole-file uploads overwrite local edits; the edit belongs in the source of the upload.

P7. A rescue outcome labelled ok can mask the primary path's failures; count failures per path.
