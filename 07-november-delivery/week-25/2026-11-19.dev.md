## 8. Patterns

P1. Step 0 of queued work: is the need still alive. Check the live system, not the seed text.

P2. A seed's diagnosis is a claim from the day of writing. Reread the cause (clock skew vs stamp age, missing retry vs uncaught subclass) before fixing.

P3. Count closures by current state carefully: a reused slot title gives an upper bound, not proven loss.

P4. Step 0 can say "alive"; a live need still needs its premise rechecked (connector conventions moved, not neighbours).

P5. A task statement can expire during the work: an ask for a persona that turns into an instrument is drift; return to the ask.

P6. A test must read the live file by path and hash; a green test on a copy says nothing about the running system.

P7. Published, delivered and used are three facts; a fresh producer proves only the first.
