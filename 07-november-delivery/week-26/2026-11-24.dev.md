## 7. Patterns

P1. An automatic re-enable reads the human's lock before acting. Cleanliness of data is not consent.

P2. A lock check must treat a dangling link as a lock, not as absence (`lstat`).

P3. A destructive command refuses empty and root paths. Shell mv/rm with a variable in the path goes through a refusing script.

P4. mv across filesystems is copy + delete. Know where the symlink points before moving.

P5. A new guard that changes behaviour under test re-runs the tests of what it silences in the same pass.

P6. A test fixture key must not be accepted as a live task by downstream guards.

P7. A probe that reads one config misses dispatchers; a door that discards stderr hides its own roots.

P8. Count outcomes over the whole window before patching.

P9. A favourable result gets a second, independent check before it reaches the owner or a public queue.

P10. Thresholds and doors stay in the always-loaded rule line; links to skills are not opened.

P11. Every file a pipe writes has a named reader. A green exit is not delivery.
