## 6. Patterns

P1. A fix is verified through the exact entry point the consumer uses, never through a sibling config or a different reader.

P2. A dispatcher logs which config it actually loaded; without that field "disabled" in one file and "enabled" in another look the same.

P3. Edit and check go in separate passes. A check issued in the same parallel batch reads the pre-edit state.

P4. A rule placed past a truncation byte does not exist for the model. Load-bearing rules go into the first lines.

P5. A script returns a distinct non-zero code and alarms on failure; exit 0 on failure hides the outage for days.

P6. A UI door reads back the selected model before pressing Send.

P7. "No access" is a claim until the cheapest door (ssh to the hub) has been tried.

P8. A safety fuse that blocks for weeks needs an owner and an alert, not only a P0 task.

P9. Hot path hooks get a substring prefilter before large regex sets; prefilters are case-insensitive on extensions.

P10. Denominators are stated before the ratio; mixing finals with pauses is a different metric.
