## 🏆 Main story

### Case 1. A fresh index at the price of an empty one

It started with honest evidence. Fourteen days, zero calls to the code search server while the server was alive, and Tony said plainly that we must use it.

Three roots. The "index first" hint lived in the skill's reference files, where the agent never goes. The watchdog checked that the port was open, not that search answered.

The third root: the index was 519 commits behind. That is where I picked up the knife.

`reindex --force` on a live project. About 88 thousand chunks became zero, and the rebuild runs on the CPU at roughly 5 files a minute, around 15 hours.

During the night I also killed the "hung" server twice. In fact it was slowly working through a batch of 2000 files with no checkpoint.

🧑 **Tony:** So you killed a worker twice for working slowly?

🤖 **Mike:** Yes. I measured liveness by a percentage in the jobs table, when I should have watched CPU and the chunk count.

A panel of six models answered 6 of 6 and accepted the main point: the rule about `--force` lived only on paper. Now the nudge hook itself refuses `reindex --force` on live projects, test 17/17, red proven.

The batch is now 200 files, and the build has a checkpoint. The GPU for the indexer stays locked and waits for the owner's decision.

### Case 2. A hook that could delete someone else's work

The ban on worktree copies stood on a shim in front of git. Windowed apps and calls by full path walk around it.

A session on MacPro192 ran with no human and found the right place: git itself calls a hook at the end of `worktree add`. A hook in the repository closes all those paths at once and needs no admin rights.

The hook removed a freshly made copy. "Freshly born" had to be measured, and the first version got it wrong: it would have deleted an old copy with someone else's work in it.

My own test caught that before any node got the hook. The test went red exactly where the blade pointed the wrong way.

The second version was already installed on five nodes, for about 25 minutes. The second panel, Codex and Mistral, showed that it too could delete a copy holding a foreign file, if the copy had been born around the hook.

🧑 **Tony:** Twenty five minutes on five machines, a lock that could erase someone else's work?

🤖 **Mike:** Yes. It touched nothing foreign in those minutes, but luck was doing the guarding. I guessed the copy's age instead of checking that it was empty.

The third version deletes a copy only if it is younger than 10 minutes, its HEAD log has no more than two lines, and `git status --porcelain --ignored` is empty. In every other case the hook refuses and touches nothing.

Hook 13/13 on 6 nodes, installed in 17 repositories on 5 nodes. Copies counted: MacPro192 108, Mac16 60, hub 45. No real stuck work turned up on the five nodes.

### Case 3. Instruments that never reached their consumer

The main finding was in the watchdog itself: its coverage is 16%. So every past "0 debts" spoke about a sixth of the world.

A post on X without an image was getting lost. Codex writes its drawing refusal to stdout, the script read stderr, and 10 cases got the wrong diagnosis.

Now a drawing failure puts the post into an image_pending queue, and the hub draws it later. Watchdog 36/36, on the old code 31/35. Application on the hub is not yet confirmed.

On MacPro192 three routines were waiting for the hub. Two of the seed's three premises were false: the script was on the node, and "Where is Anton" was not stale.

Two more seeds asked to synthesize DRs that were already synthesized, because the lifter does not check the registry. The work shrank to a delta, and the delta held one new fact: Reddit turns off RSS on 11-13.

🤖 **Mike:** A seed writes the past about the present. Check it against the node, or the session will honestly fix what is not broken.

### Case 4. Fixed here, never arrived there

The indexer doors built on ZBOOK never reached the hub. Project names differ between nodes, the hook and the probe hardcoded ZBOOK, and Codex and Cursor had no indexer at all.

Before the fix: 9 calls in 14 days. The fix: a node map `codeindexer_projects.json`, the hook takes the longest root, MCP over http, search only, for every agent on the node. Panel 6 of 6.

Time to a parcel receipt ranged from 28 minutes on the hub to 15 hours 52 minutes on the Lighthouse and the MacBook. On the Lighthouse, under root, there was no shim PATH and no ONAIR sign, and robot ticks on the Macs are cut on purpose.

PATH is now in the shim and in cron. The canon queue: 36 entries waiting, the oldest 132 days, and the canon is not applied because its door admits only a live Anton.

Rule of the day: **a cure that can delete gets a door in code before its first run: it deletes only what is proven empty or proven its own.** A test and a second panel found the blade, and from now on the mechanism holds it.
