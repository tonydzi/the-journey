# Day 161 - 2026-11-11: a verdict hangs on one line; the honesty of a benchmark claim, a stop hook, an exit-code check and a health watchdog each reduced to a single setting

Dev-log form. Assembled from 29 retros (1 personal not retold; names from the Plaud review omitted) and one canon beat, `beat-2026-11-11-threshold-honesty`.

Defect: a verdict (claim, block, green, red) is determined by one parameter that is not displayed next to the verdict. Change the parameter and the same code yields the opposite verdict.

Position on the line: 158 count without denominator; 159 foreign bytes at home; 160 receipt before the fact; 161 verdict hangs on one hidden setting.

## 1. "Three times more honest than Mem0" = one threshold line

Problem: memory benchmark claim. Honest refusal 0.45 vs Mem0 0.14; table: correct refusals 10/22 vs 3/22 (Mem0) and 4/22 (third entrant). Recall@5 0.88 vs Mem0 0.87, Fidelis 0.86, BM25 0.77.

Cause: replay over 91 saved answers: with the refusal threshold 10/22, without it 3/22 (Mem0 also 3). Cost of the threshold: +12 false refusals of 69.

Solution: claim restated as threshold + effect + cost. "Three times" holds only as the refusal share on unanswerable questions.

Pattern: a comparative claim carries the parameter it depends on and the parameter's cost; replay with the parameter removed before publishing.

## 2. Stop hook opened by an unknown word

Problem: stop hook against false "no" read any "no" about another object as "file does not exist".

Cause: fixed earlier with an allowlist of harmless words; any word outside the list opened the door.

Solution: denylist; the block lifts only on a positive marker of a different object. Test 19/19, opponent corpus 60/60.

Pattern: a guard defaults closed; an exemption requires a positive signal, never absence of a known one.

## 3. `set` between a command and its exit code

Problem: nightly sync reported exit=0 since 04.11 while the profile was logged out.

Cause: any line between a command and the read of its return code resets or masks it. Here: `set` in a `.cmd`; the hook did not handle `.cmd` or substitution.

Solution: the existing door was widened; no new robot. 14 mutations red; class family 14 cases since 03.09; sweep of 27 thousand commands, 35 new refusals.

Pattern: capture the return code on the line immediately after the command; a check that reads it later must prove nothing sits in between.

## 4. Red by guess

Problem: browser-rail watchdog marked the rail red.

Cause: red was set on restart plus silence, with zero attempts ("idle != down").

Solution: red only at >=3 failures after the last success. Test 35/35; 5 nodes on the new version.

Pattern: a failure verdict requires attempts; silence is "unknown".

## 5. Mac16 morning slowdown: root elsewhere

Problem: Mac16 slow in the mornings. Nightly brain eval on CPU 6-8 h; window lock gated start only. agents-python 492% night, 320% morning, 28% day; 140/184 questions at SIGSTOP.

Cause: the hub already runs the same eval on CUDA (370-942 s per run) on a fresher index (108116 chunks vs Mac16 107131).

Solution: patch first (end cap 05:00 UTC), then root: eval on hub only; Mac16 launchd job disabled, not deleted. Hub: title 0.95, body 0.85, bridge 0.43, temporal 1.0.

Pattern: before optimising a slow job, check whether another node already produces the same output.

## 6. Fix not applied at the consumer

Problem A: rail-plan lock lost its stop at move 8. Cause: on 04.11 a tool intake replaced the file with the hub's same-name version. Declared plans: 13/32 before lock, 32/35 with it, 32/67 after the swap.

Solution: stop branch restored, 57 checks.

Problem B: MacStudio lacked the browser counter hook; rollout never reached it. Solution: 4 files + watchdog agent; Write/Edit/Agent were not routed through the dispatcher before.

Problem C: class "script delivery without an applier": Studio 221 files vs hub 3309; live node without mirror counted as "unknown". Solution: live without mirror = red; detector fixed on one node only. Class open.

Problem D: rollback reported "file was not there". Cause: unreadable hash read as absence; literal `%USERPROFILE%` in path. Solution: separate EXISTS/ABSENT probe.

Old 53/56, new 56/56, then 59/59; applied 4 of 8 nodes, 3 offline.

Pattern: a fix is done when read back at the consumer on each node; a same-name file from another node is not proof of the same content.

## 8. Patterns

P2. Replay with the parameter removed before a comparative claim leaves the house.

P7. A fix counts only when read back at each consumer.
