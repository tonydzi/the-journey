# Day 127 - 2026-10-08: a verdict type without an unknown value prints blindness as fact, and a family counted by name never reaches three

Dev-log form. One pattern in eight instances, plus one human counter-example.

The unifying failure mode of the day: the verdict's type system had no representation for ignorance, so an absence of evidence resolved to a default and was emitted as an established value. In every instance the default was the convenient one.

Position on the line. Day 125: a record of required behaviour was accepted as enforcement. Day 126: the scope of the probe was accepted as the scope of the world.

Day 127: the instrument had no way to *report* its own scope, because its output type did not admit it.

Scale of the day: 31 distinct sessions, 111 calls, 112 robotic, 23 retrospectives, 17 vault commits, 48 config commits, 0 commits to this book, 7 decisions, 3 research orders.

---

## 0. The shape of the defect, and its enabling second layer

**Layer one, the output type.** A verdict enumerated as `{core, adjacent, off}`, `{TAKEN, FREE}`, `{clean, dirty}` has no member meaning "insufficient evidence". The absence therefore maps onto whichever member the code reaches by default, and callers cannot distinguish a measured verdict from a default one.

**Layer two, the self-measurement.** The policy "build a mechanism after the third dated case" depends on a counter. Today that counter failed in both directions in the same day: understated where one family lived under three or four class names, and overstated where a check read `len()` of a two-element tuple and therefore saw 3 on every first case.

Consequence: layer one is a defect that layer two cannot escalate. Both must be fixed together, and the fix to layer two is the one that compounds.

**Required output contract.** Every instrument report prints `cannot judge N of M, reason`. An instrument whose reports never contain that line is not careful; it is blind and unaware.

## 1. A verdict with three values and no fourth

**Problem.** A foreign-repository selector judged domain fit from a one-line description, emitting `core | adjacent | off`. Empty description and no topics produced an affirmative `off`.

**Evidence.** 53 universe rows had an empty description: 43 marked `off`, 6 `core`, 4 `adjacent`. Drift check over 1850 universe rows after the fix: 0 divergences. 77 rows had nearly moved to `adjacent` silently.

**Root.** The verdict was typed as levels of interest, with no axis for input sufficiency, so no-evidence fell to the default.

**Fix.** Fourth value `unknown` added; input declared as an explicit evidence-field list; evidence fetch moved inside the door rather than the caller.

**Counter-defect in the first fix.** The first revision gave a deciding vote to the thread title, which we select ourselves. The thread now occupies its own axis and may only confirm, never assign.

**Measurements.** Test 57/57, 11 failing before. Mutants 9/9 killed, M8 surviving initially.

**Family.** 7 dated cases (September 8 ×4, September 14, September 21, October 5). The §5.10 threshold was crossed on September 14, three weeks before this fix.

## 2. A silent cap read as the size of the world

**Problem.** An instrument's sample ceiling was an argparse default. It stopped at the ceiling and emitted no line about it, so the count read as the population.

**Root and why it survived.** The default's blind spot swallowed the founding cases of its own class. The breakage lived under four class names, so the threshold arrived under none. Honest family size: 6 cases since September 3, against 1 to 2 visible.

**Second, independent finding.** 64 verification instruments were outside version control: an ignore rule on the lint file prefix hid the linters themselves from git. In git there were 0.

**Fix.** A dedicated silent-cap linter, a family-to-door map in the breakage counter, and the ignore rule corrected.

**Measurements.** 182 finds across four classes (32, 32, 25, 93), coverage 99.9 per cent, test grid 34 checks and 16 mutants. Rollout to the hub failed that day: ssh dead. Recorded rather than swallowed.

**Pattern.** A limit that is not in the output is indistinguishable from the absence of a limit. Emit the cap on every run, reached or not.

## 3. The `cannot judge` line, measured for the first time

**Problem.** "This test is isolated from production data" was an unverified claim treated as a property.

**Evidence.** Of 93 foreign tests: 16 write to production, 57 clean, **20 cannot be judged**. The first edition of this measurement produced a different, understated number because three holes in the measuring instrument were still open.

**Root.** The number of ways to substitute a write path is unbounded: environment variables, home directory, a module constant, a default argument. The instrument enumerated methods instead of asserting the consequence.

**Fix.** The guard now judges the fact of a write outside the temp directory, default mode `block`. Parcel for 8 nodes. A wrapper-function-as-descriptor bug that broke `Path.mkdir` was fixed along the way.

**Not fixed.** 16 guilty tests remain, named individually.

**Measurements.** Guard 61/61, self-test 18/18, mutants 18/18 killed. The family lived under 3 class names, so §5.10 was understated.

**Pattern.** Catch the consequence, not the method. A method enumeration is open-ended and its coverage is unknowable; a consequence assertion has a finite surface.

## 4. A denominator containing the impossible

**Problem.** Several instruments computed ratios over denominators that included forbidden or unreachable members, producing flattering values.

**Evidence.** 63 requesting repositories, 5 of them with 0 foreign open pull requests, so nothing there is reviewable. The batch version of the instrument had 13 per cent coverage (60 of 69 answers were "don't know") against 100 per cent on a per-repository probe.

**Root.** No shared contract existed stating that a denominator contains only the permitted and the possible. Each author held the boundaries in memory and omitted one.

**Fix.** `_shared/denominator_guard.py`: the contract plus a ratcheted sweeper that scans for division by a name. Three of four cases closed; parcel for 8 nodes.

**About the detector.** The first revision returned 2780 places across 642 of 954 files, 67 per cent of the codebase. That is a flooder, not a finding. Narrowed to 174 places in 102 files.

**Measurements.** 17 checks, 26 mutations red. Fourth dated case of the family, caught during the repair itself.

## 5. An unfinished search reported to a human as an absence

**Problem.** Asked about a conference, a session launched a background vault search and reported "zero mentions in the vault". The search had not finished. The mentions existed.

**Why this instance is the most expensive.** In the other seven cases an instrument misled an instrument. Here an instrument misled the human, and a decision was made on it.

**Same family, same day, second session.** The machine timezone (GMT) skewed an entire calendar triage, and a background search over a folder of 9412 markdown files produced a false "nothing found". 88 events in the window, 31 on Thursday, 1 surviving.

**Third instance, not about instruments.** A redundant geography question was put to the human whose answer was already in the vault. Declaring your own ignorance without checking it is the same defect.

**Fix.** A live-rail reminder placed as a pre-tool hook on search calls, and a second guard on relative time inside long-lived artefacts, because "today" in a note expires silently. Both doors stand on one node; the counterpart for the other operating system is not written.

**Operational rule.** A background search has finished only when its output file has been closed with an exit marker. Until then the only legitimate output is "I have not found it yet".

## 6. A fail-open accepted an invented identity as lawful

**Problem.** The order of the day extended machine stamping from Claude Code sessions to any agent and any write. The measurement found the stamp on 4 of 20 fresh artefacts; a full pass of 33 files gave 3 lawful, 29 unstamped, and 1 **lying**, with an invented node name.

**Root.** The exception handler was fail-open: on any verification error the name was accepted. The instrument did not know the fleet node registry and could not emit "not in the registry".

**Second defect, same instrument.** A regex without multiline mode read the field as empty, producing 4 false positives.

**Fix.** `machine_stamp.py` with `line` / `apply` / `lint` over the canon key; an unknown node prints as not-in-registry; editing another agent's stamp requires an explicit force flag. A competing custom key was rejected by external review in favour of the canon one.

**Measurements.** Guard 29 checks, 15 breakages red, probe 12/12, parcel for 8 nodes, hub applied. The rollout gates rebuffed four attempts in a row, recorded.

**Pattern.** Identity verification must fail closed. A fail-open identity check converts every error path into an authentication bypass.

## 7. A door on the generated layer only

**Problem.** A stop-word door guarded the layer assembled by the CV generator: 20/20 clean. The live violations sat in handwritten files of the public profile, which the generator never touches.

**Root.** The door guarded the exact file name the stamp happened to know, rather than every surface where the text lives (support, citation, robots, methodology, localised readme).

**The pattern was blind twice.** It missed the forbidden word in bare form and fired falsely on a lawful compound. The false positive is worse than the miss: it trains the author to route around the door with a bypass marker instead of fixing it. An 18-case edge table found 3 template defects.

**Narrow versus honest fan-out.** Narrow (6 file names): 157 hits. Honest (all text files): 2767 files read, 0 cannot-judge, **823 hits across 20 repositories** - 5× the narrow fan-out and 20× the hosting platform's code search.

**Distribution.** 406 in this book and a neighbouring repository (the owner's product decision, untouched), 183 in research, 120 in dashboards, 55 fixed in the starter kit, 10 in the public profile (3 fixed, 3 left deliberately).

**Corroborating number from a neighbouring session.** Hosting-platform code search returned 11 hits where 54 exist, an undercount of 5×.

**Pattern.** A foreign index's recall over your own text is between 5 and 20 per cent on two independent measurements this day. Never use it as a coverage instrument.

## 8. The family counter read the length of a tuple

**Problem.** `_warn_if_family_is_older` computed `len(prior_art.scan_class(...))`, but `scan_class` returns `(hits, n_lines)`. The length is always 2, so `BREAKAGE_STRIKE=3` was crossed on every first case.

**Why it compounds.** This is the instrument that gates mechanism-building. It lied in both directions on the same day: overstating here, understating in sections 2 and 3.

**Fix.** `split_class_hits(top=None)` and `family_prior_count` replace `len()`. The round-trip test runs against a copy of the vault, not the live one.

**Surfaced during the repair.** The final recheck found 5 new failures inside its own just-closed test. 6 rows of 715 had polluted the live journal. A sender invoked without flags sent a task twice in the wrong form.

**The day's worst number.** A copy sweep found 23 copies of one sender file with 9 distinct checksums. The class "a flag leaks into the message body" holds 5 dated cases since August 17; the fix has existed since September 23 and has reached **zero** nodes.

**Also recorded.** A follower node ran 962 commits and 731 changed files ahead of the front. The always-loaded canon file is 124467 bytes against a red cap of 120000.

**Pattern.** The arity of a return value is not evidence of seriality. And "we already understood this" is not "this is deployed": a fix with a registered parcel and no applied node is a fix that does not exist.

## 9. The rule of the day

**A verdict type must admit `unknown`, and every instrument report must print `cannot judge N of M, reason`. A breakage family is counted by defect, not by the name the case was filed under.**

Operational consequences:

1. Enumerate verdicts with an explicit insufficiency member. Never let no-evidence resolve to a convenient default.
2. Emit the sample cap on every run, reached or not.
3. Denominators contain only the permitted and the possible.
4. Identity checks fail closed; a fail-open `except` is an authentication bypass.
5. Catch consequences, not methods, when the method surface is open-ended.
6. A foreign index is not a coverage instrument. Measure your own text yourself.
7. The counter that gates repair policy needs its own red proof, in both directions.

## 11. The human counter-example

The owner sent six of the bot's messages into the chat and wrote "WHY??".

He refused to accept the count of junk messages as an answer and demanded the cause. The cause turned out to be two distinct defects with different cures: a snapshot write destroying a neighbour's marks, and a proof builder crashing inside a live loop with no expiry on the waiting state.

The same move appears in his stamping order the same day: he did not ask for more stamps, he named the invariant ("any agent, any write, state the machine") that makes the absence of a stamp detectable.

Both are the move none of the day's instruments could make: asking what the number is evidence *of*.
