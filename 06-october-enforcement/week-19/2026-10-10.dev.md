# Day 129 - 2026-10-10: a change reached one half of a pair, and no one enumerated the consumers before the fix

Dev-log form. One pattern in nine instances, plus one human counter-example.

The unifying failure mode of the day: the object being changed had more than one consumer or more than one controller, the change was applied to one, and no step of the fix enumerated the others.

Position on the line. Day 128: a claim was true at write time and stale at read time (the time axis). Day 129: a claim is true for one consumer and false for its twin (the space axis).

Scale of the day: 7 distinct live sessions, 13 calls, 277 robotic, 12 retrospectives, 13 vault commits, 40 config commits, 0 commits to this book, 4 decisions, 0 research orders.

---

## 0. The shape of the defect

A component `X` has consumers `{A, B, ...}` or controllers `{P, Q, ...}`. A fix `F` changes `X` for `A` (or adjusts `P`). Nothing in `F` enumerates `B` (or `Q`). `B` keeps the old behaviour; `Q` keeps acting on assumptions `F` invalidated.

Required contract: **a fix begins with the consumer set of what it changes, and a parity instrument compares every member after the fix.** A migration without a parity check is half a migration by default.

## 1. The daemon diet reached one agent

2026-08-03: shared MCP daemons replaced per-session stdio launches for Claude. The Codex contour stayed on stdio and spawned a Telegram MCP per thread: 4 concurrent copies, each with its own login. Symptom: `thread/resume` waited 360 s, MCP init 120 s.

Fix: one daemon serves `/sse` and `/mcp` from one process; Codex uses Streamable HTTP. Measured: 4 accounts in 26 s, 122 tools over both protocols, new sessions in 5-9 s.

Side find: another server failed on every start because `python` on PATH lacked the `mcp` package. Codex's log self-trims; capture the "before" measurement immediately.

## 2. Contour parity instrument

`mcp_contour_parity.py` compares both configs: FAIL on daemon-vs-stdio split, wrong protocol path, broken token; token via `bearer_token_env_var`, literal forbidden. Prints `cannot judge N of M`.

First live run: 11 servers, FAIL 0, WARN 1, OK 9, cannot judge 1. The WARN was a messenger server still on stdio for Codex. Test 30 checks, red x4; three review rounds, panel 6/6.

Wired into the nightly sanitiser. Not verified: the first nightly run, live runs on Mac nodes.

## 4. A watchdog and a reaper on one daemon

Shared Telegram MCP daemon on the hub: 11 consecutive deaths at age 72-74 min, launches at :44 terminated at :57-:58. Killer: orphan-reaper task every 15 min. The watchdog started the daemon via `Start-Process` and exited; the cmd wrapper became an orphan; the reaper killed it with descendants.

The janitor log was silent in the death windows.

Control: a scheduler-launched daemon (parent `svchost`) had lived for days until 2026-10-07.

Fix: the reaper excludes the shared daemons' ports and their ancestors (DryRun 2/2 vs 0/2); the watchdog raises via a scheduled task. Third reaper to kill a shared daemon (08-02, 08-03, 10-07). No shared registry of protected processes yet.

PowerShell 5.1 traps: `Start-Process -Wait` waits for descendants; `Stop-ScheduledTask` stops only the cmd wrapper, python survives.
