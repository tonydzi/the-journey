# Day 128 - 2026-10-09: claims that were true at write time kept being enforced after expiry, because none of them carried their age

Dev-log form. One pattern in eight instances, plus one human counter-example.

The unifying failure mode of the day: a claim that behaviour depends on was correct when recorded, carried no timestamp of its last verification, and continued to be acted on after the world changed underneath it.

Position on the line. Day 124: a record was false at birth and accepted as the thing. Day 127: the verdict type could not express ignorance.

Day 128: every record was true at birth. The defect is the missing age field.

Scale of the day: 34 distinct sessions, 100 calls, 202 robotic, 18 retrospectives, 14 vault commits, 48 config commits, 1 commit to this book, 1 decision, 6 research orders.

---

## 0. The shape of the defect

A claim `C` is written at `t0` and read by consumers at `t > t0`. If `C` has no `verified_at` and no guard on `now - verified_at`, consumers cannot distinguish a fresh claim from a stale one. The convenient reading wins.

Required contract: **a claim that gates behaviour stores the time of its last successful verification, and a guard outside the claimant judges that age.** Liveness signals do not satisfy this contract; only the age of the last successful output does.

## 1. A daemon outlived its library

Call-monitor daemon, started 2026-09-29. On 2026-10-02 ~19:11Z the Python stdlib tree was deleted on the host and restored by hand. Modules already imported survived in memory; the calendar API discovery JSON was read from a path that briefly vanished.

Result: 1436 poll errors between 2026-10-02 19:15Z and 2026-10-09 22:35Z. Heartbeat green throughout. A fresh `build("calendar", "v3")` succeeded.

Root layers: error logged as `str(e)` without traceback; heartbeat called after `try/except`, so it proved liveness only; no guard on age of last healthy output; supervisor restarts dead processes only.

Fix: atomic last-ok file, `[poll] ok` line, full traceback on change of error text, guard on age of last healthy poll (threshold 30 min, alert at most every 6 h, heal at most every 2 h), scheduled every 15 min. Test 13/13, 3 mutants red. Declared blind spot: 00:00-06:00 Lisbon, the daemon does not poll.

## 2. A dead git channel kept file ownership

Three delivery rails for fleet tools: sync share, nightly parcel, git channel. Since 2026-08-20 the parcel receiver skips 88 files "owned" by the git channel. The channel head has not moved since 2026-09-21; the hub is 2136 commits ahead; no push task exists.

Receiver report `differs: 0` was true for the parcel and false for the node. 18 days without a live rail for those files.

Refuted first: the morning diagnosis named a hub-side sync exclusion as the root. It was a protection; diagnosis had used one rail of three.

Fix: `channel_owned()` reads head age; older than 7 days or unreadable means dead, ownership released with a loud line. Applied: 64 files updated with backup, 67 locally newer left alone.

## 3. A refresh token revoked silently, alarms to an unread chat

Mailbox refresh token revoked ~2026-09-22. Connector health yellow from 09-23, 5 probe alarms from 09-24, all routed to a service chat with no reader. ~16 days blind. Calendar probe for the same mailbox on the hub: 20 DEAD rows and 30 ALARM rows in 17 days.

An alarm without a reader is a log entry.

## 4. A repair recipe valid only on its author's node

The recipe embedded in the alarm failed on the hub with `FileNotFoundError`: the script's config held a literal secrets path correct on the laptop.

Fix: candidate ladder (env, literal, home-relative), a candidate valid only if the client credential file exists inside. A later commit added strict env validation at import and would have broken the call monitor; caught by panel. Red probe: 6/10 original, 3/10 second commit, 10/10 on both nodes.

## 5. Sync overwrote a file and dropped a code section

2026-09-15: sync overwrite removed `EXPIRY_STORES` from the token probe. Its test stayed red 24 days. Regression grid: 290 of 1422 red (20%).

One red among 290 carries no signal.

Restored from sync version archive. Stores now bound to node role; on a peer they print `NA` and the summary prints `cannot judge 2 of 7`.

Second defect: the probe's tests invoked it with the live log writer and appended fake ALARM lines to the production log. 235 such lines on the laptop since 2026-08-30, 34 written by the agent on this day.

## 6. A ban list met a third name

Rule: no session cards that wait for a human click. Guard blocked one start mode by name and treated another as human choice. 10-08 the first leaked; 10-09 the second.

First fix appended the second name. A six-model panel ($0.086) unanimously predicted a leak on the next name. Guard inverted to an allow list: only an explicit user request and start by proposal id pass; empty value and case variants count as cards.

An enumeration of forbidden names is the claim "no other names exist", true until the next upstream release.

Verification trap: PowerShell 5.1 corrupts JSON on stdin; the guard reads it as empty and passes. Live probes go through bash or `.cmd`.

## 8. A model table windowed by file mtime

Passive count over 5737 transcripts across 60 days inflated one model from 51 to 3439 turns because the window used file mtime. After fixing, intra-family differences were 2-4.5% and confounded with era. Decision: only an active trap-based eval ranks; passive counts remain a tool-failure signal.
