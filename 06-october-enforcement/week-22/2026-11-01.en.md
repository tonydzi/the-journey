**Edge of the day, as a formula: "newer does not mean right: in a shared file without one writer, the last copy wins."** When several machines edit a file and nobody owns it, the best version doesn't survive. The one that landed last does.

## 🎬 Cold-open

One node copies a fresh version of the approval script to its neighbour. The copy is newer, so it must be better.

The new copy has no `chat` command. The test goes red and stays red for five days.

🧑 **Tony:** Why did nobody notice for five days?

🤖 **Mike:** An unknown command exited with code 0. The script answered "all good" to a call for something it no longer had.

## 📌 TLDR

**The main thing.** Four shared files broke the same way: each had several writers and no single source. Each time the last copy won, and the right one lost.

**What got fixed.** The approval script is now one version shipped through an installer. The deploy register is merged into one version, and the parcel courier decides "newer" by version instead of file time.

**What didn't.** The memory index grew back and its guard is red again. The "one writer for the fleet" decision belongs to Anton.

## 🏆 Main story

### Case 1. The approval script and five red days

#### Where the file lived

`approval.py` sits in each node's scripts folder. That folder is not synced.

So every node had its own fork. A file that was shared in meaning lived as several independent copies.

#### How the command vanished

Someone copied a version from one node to another. The copy was fresher, and it had no `chat` command.

The test went red. It stayed red for five days, while live calls kept getting code 0.

🧑 **Tony:** Code 0 for a command that doesn't exist?

🤖 **Mike:** Yes. The script didn't know the command and quietly exited "successfully". The red test was shouting while the working path said everything was fine.

#### What was done

One version, md5 a73823ce, goes out only through an installer. 9 tests and 28 checks, 4 builds.

It is live on the running nodes. Four nodes are offline, and one laptop's fork is not merged yet.

### Case 2. The deploy register and a whole-file parcel

#### Three versions

`deploy_register.py` lived in three versions. Each carried its own fixes.

An old parcel carried the whole file. It landed on top and erased the fixes made after it was sent.

#### The merge

The merge went line by line: 29 and 11 against 26 and 13. The result is one version, d52c068f.

A second hole turned up on the way. A parcel with no `--tier` silently became manual and waited for a human nobody had told.

🧑 **Tony:** So a whole-file parcel is more dangerous than a patch?

🤖 **Mike:** A whole file carries everything that was known when it was sent. Everything learned later, it overwrites. A patch touches only its own lines.

#### Where it stands

The gate is on 8 nodes, applied on 5. Three colleagues' nodes are dead.

### Case 3. A courier that read file time

#### Errno 9

The parcel courier failed on Windows with Errno 9. A homemade installer called `os.fsync` on a descriptor opened read-only with `"rb"`.

That was the first break. The second was quieter and mattered more.

#### Who is newer

The courier judged which file was newer by modification time. Modification time changes with copying, syncing and any touch.

An old version copied yesterday looked newer than the right version from the day before.

🧑 **Tony:** Was there a version inside the file?

🤖 **Mike:** There was. The courier didn't read it. It looked at the date on the envelope, and the post office stamps that date, the author doesn't.

#### Courier 2.0.1

Now "newer" is decided by version, not time. The channel is chosen by bytes, and the target is opened read-only.

44 checks, mutants 22 of 22. On real files it fired in 1 case of 4219.

Live on three nodes, two offline.

### Case 4. A memory index everyone writes

#### One file for the fleet

`MEMORY.md` is one file for the whole fleet. Many write to it.

It was folded: 479 lines, then 96, then 120 again. In bytes: 93869, then 16998, then 22063.

#### Why it grew back

One pass does the folding. Everyone else appends, one line each, each from their own machine.

The guard is red again. The fold was right, and then others wrote after it.

🧑 **Tony:** So fold it once more?

🤖 **Mike:** We fold it, and in a week it grows again. While the file has many writers, the last one is always right. "One writer for the fleet" changes how the fleet is built, so that call is Anton's.

### What follows

Approval script: a fresh copy missing a command. Deploy register: an old parcel carrying a whole file.

Courier: file time instead of version. Memory index: the last writer after the fold.

Rule of the day: **a shared file needs one source and one write door; "newer" is decided by the version inside the file, not by time, arrival order, or whose copy landed last.**
