## 🏆 Main story

### Case 1. A word in a report

#### What was being guarded

The token-spend-watchdog routine ran four times overnight. Its job: notice a yellow spend alert and deliver it.

Yellow alerts reach Telegram. They don't reach WhatsApp.

#### Two causes, one hole

The first cause is plain. An unattended session has no WhatsApp tool; the rail answers locked or unavailable.

The second is subtler. The hook took a word in the report for a session launch and cut the message.

🧑 **Tony:** So the hook was in the right place and fired on the wrong thing?

🤖 **Mike:** It stood where it was told to stand. It was shown a word, and the word matched. To the hook, a report about an act and the act itself look the same.

#### What came out the other end

Yellows go only to chat 03. The second door is silent.

The tail is written down plainly: yellow delivery to WhatsApp needs fixing. That takes either a tool in the unattended session or sending by script.

### Case 2. One topic, two languages

#### An order and its twin

A session was starting a DR on free tiers. It built dr_start.py, test 4 of 4.

Meanwhile the same order showed up at Codex. The session removed the duplicate itself, by noticing it.

#### Why the check stayed quiet

The order duplicate check was in place. It compared the texts of the orders.

The same topic written in different languages is, for the check, two different orders. The letters didn't match, so there was no duplicate.

🧑 **Tony:** And if the session hadn't looked for itself?

🤖 **Mike:** Then two DRs on one topic would have gone to work. The check would have been green, and it wouldn't have lied: the texts really are different.

#### The tail

The session finished its work. One line remains in the tail: the duplicate check is blind to topics in different languages.

### Case 3. A name that lies and stays

#### What the name says

The night retro file is named "...62-sessii". There are 29 sessions inside.

The number in the name is wrong. Anyone looking at the file list reads "62".

#### Why it wasn't renamed

mark-done points at the file name. Renaming it would break the link, and the done mark would lose its file.

So the name was kept on purpose. The lie in the name is closed by a note in the body that says how many sessions there really are.

🧑 **Tony:** Strange to leave an untruth in plain sight.

🤖 **Mike:** An untruth in a name is cheaper than a broken link. A person reads the name, a machine reads the link. We left the person a correction inside and left the machine its path.

#### What it teaches

A file name is a surface too. A guard that counts by names would have counted 62.

### What follows

The hook read a word. The duplicate check read letters.

The file name stated a number that isn't inside. Each time the guard saw exactly what it was shown.

Rule of the day: **a guard that compares form catches only form; where meaning matters, you need a check of meaning or a note that carries it.**

## 🎞 What else happened today

### Case 4. The content miner and a length threshold

#### The scan

On 10-31 the content miner walked the session list: 409 sessions in all.

All of the top 30 turned out to be noise: skill exams. They passed the selection threshold on length, not on content.

#### The third time

This is the third such case in a row, counting from 10-25. A workaround is in: a prefix filter and a limit.

The root is not fixed. The filter should run before the limit; for now the limit cuts the top before the filter gets to throw out the noise.

🧑 **Tony:** A long session usually has substance, doesn't it?

🤖 **Mike:** Usually. A skill exam is long too, it's just about something else. Length is easy to count and meaning isn't, so the threshold looks at length.
