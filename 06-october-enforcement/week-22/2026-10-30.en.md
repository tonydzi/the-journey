## 🏆 Main story

### The receipt that arrived last

#### What was asked

The X reader for CRM M07 was reviewed from source. The data owner's answer gave three numbers: 190 mentions, 0 direct messages, 32 receipts.

Direct messages were blocked by authorization, HTTP 403. Mentions kept arriving fine.

🧑 **Tony:** One hundred ninety of them. Looks like a live channel.

🤖 **Mike:** It looks exactly like one. But mentions and direct messages walk through different doors, and a full first door tells you nothing about an empty second one.

#### Two copies, one defect

The two copies of the reader matched byte for byte, 20968 bytes each. So there is one defect, and it lives in both.

After a late HTTP error the collector honestly wrote "partial". Then, having finished the rest of the pass, it also wrote "ok".

#### What the consumer reads

Anyone who takes the last receipt gets "success". The overall exit code 0 does not prove that direct messages arrived either.

🧑 **Tony:** So the code told the truth about the process and a lie about the result.

🤖 **Mike:** The code said the process didn't crash. About what the process brought back, the code is silent.

The panel, $0.129, accepted 3 refinements and rejected 5 groups of assumptions. Tests and requests to the source were not run in this pass, so the fix here exists only in words for now.

### A zero from the profiler

#### Large and small

Touchbase was tried with a large run: a check over 400 records. The run hit the 300.407 s limit, ended in a timeout, and no new queue appeared.

A small run with a profile, 20 records, finished in 124.594 s and produced a queue of 10 rows.

🧑 **Tony:** The small one passed. So the large one will pass too, given time?

🤖 **Mike:** The small run proved that the small run works. About the large one it said nothing, except one thing: time goes somewhere, and now we know where.

#### Where the time goes

In the profile, the build took 121.5 s. Inside it, fact collection took 81.6 s and the card index 73.6 s; calculations took 39.2 s.

The main suspect: 19 853 file reads. A suspect, not yet a culprit.

#### A code that wasn't there

The profiler returned exit code 0. The exit code of the app itself was never captured: the wrapper swallows SystemExit.

So the instrument was reporting on itself. The app could have exited with any code, and we would not have known.

🧑 **Tony:** And the metrics?

🤖 **Mike:** The metrics doubled. 82 physical copies against 41 logical events: a metric record carries no session PID, so two copies of one event look the same as two events.

The panel, $0.081, accepted 5 refinements and rejected 18. The cause of the earlier timeout is not proven, and that is how we write it down.

### A stand that read the wrong file

#### Six findings

Stand V2 checks ACK and delivery over the bus. An independent review requested changes: 6 findings, 2 medium and 4 low.

Exit codes on the run: child 0, broker 3, outer PowerShell 1. Three processes, three different answers.

#### Twelve of fourteen

The fixes are written down. They have not been checked by new tests.

Of 14 tests, 12 passed. Two failed because of a bug in the stand itself: the test expected a list of arguments and got a command string.

#### A false mutation

3 mutation checks were run. On broken code they failed; on healthy controls 3 of 3 passed.

The first "mutation", though, turned out to be false. The stand was reading a source file that was not the mutant.

🧑 **Tony:** So the test went red, and we almost believed it went red on the right thing.

🤖 **Mike:** It went red on something. Checking a mutant starts with asking which file the stand actually opened.

The panel of 6 models, $0.0738, accepted 6 refinements and rejected 21. The retro states its turn plainly: a green shell exit code, exit 0, may not be presented as acceptance in a retro.

### What follows

The "ok" receipt came after "partial". The profiler returned its own zero instead of the app's code.

Child 0 stood next to broker 3. A small run was about to be read as a large one.

Rule of the day: **the final status is written once, after every step, and names which process and which mode it describes.**

## 🎞 What else happened today

### Podcasts: the text stays, the local audio goes

#### What was decided

Podcast texts and transcripts stay. Local audio is deleted.

Cleanup no longer waits for YouTube. The two processes now have separate temporary copies and stay out of each other's way.

#### The big pass

The pass ran from Oct 29 23:52 to Oct 30 02:33 UTC. In that time: 410 paths, 177 deletions totalling 9 648 134 606 bytes, 224 copies kept, 9 errors finding the original.

One more copy of 31 415 398 bytes had been deleted earlier by a probe. 186 old audio files out of 364 remain.

#### Why the cleanup is fearless

Deletion happened only after a SHA256 comparison of the whole file. A byte-for-byte match meant the copy was redundant; no match, or no original found, meant the file stayed.

After deletion, the note and transcript hashes matched for all 177 files. The 224 kept copies and the 9 lookup errors show the rule worked in both directions.

🧑 **Tony:** A hundred seventy seven files deleted, and that's not scary?

🤖 **Mike:** What's scary is deleting something when you don't know whether it has a twin. Here every deleted file had its twin checked down to the last byte.

#### A drop that was no failure

The backup used to break off at 300 seconds. Now it waits up to 1800.

A dropped SSH connection was taken for a failed job. The job on the far side kept going.

🤖 **Mike:** The channel dropped and we lost sight of the process. The process didn't stop because of that; nobody told it to.

YouTube uploads: 0, the Google sign-in is not completed. Panel $0.062.

### Touchbase: one live test

#### Old against new

The new calculation was compared with the old one on a real dialogue. 5 checks of 5 green.

One logical metric event: a duplicate by ID across two copies of a file. 17 pins.

#### Narrow bounds

The coordinator accepted the result within narrow bounds. The retro's turn: preparing a launch may not be presented as a launch.

The timestamp of the SHM service file changed all the same. Who changed it is not established.

🧑 **Tony:** So we launched nothing, and the file changed.

🤖 **Mike:** Something touched it. Until we know what, we write "not established" and don't invent a culprit.

Panel $0.095: 14 refinements accepted, 12 rejected. The memory search was silent for several minutes and was interrupted.
