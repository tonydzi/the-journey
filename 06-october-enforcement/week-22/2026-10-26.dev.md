# Day 145 - 2026-10-26: symptom located where a resource or a work class had no owner

Dev-log form. First day of week 22.

Defect: symptom `S` appears on resource or work class `R` that has no designated owner: N uncoordinated copies share `R`, or `R` is refreshed only as a side effect of another process, or `R` arrives with a detector but no executor. Fixing `S` without naming an owner for `R` does not hold.

Position on the line. 141: green receipt over a dead output. 142: a true number went stale before use.

143: verdict from one layer. 144: counter measured by a foreign definition. 145: no owner for the resource or the work.

## 0. Contract

Shared stateful resource (browser session, lock, port): exactly one long-lived owner process; clients connect, never spawn their own. Config block on a node: has its own healer, not only a parcel side effect.

Fleet exit code: computed over reachable/connected nodes only; unreachable = separate list. Version conflict: receiver-newer wins unless sender proves newer (`newer_local_reason`).

Work class arriving on a bus: needs a standing executor; an inbox robot that only ACKs is a detector. A memory of absence ("X does not exist"): closed by fields when refuted, never left as an active stop.

## 1. Shared Firefox-MCP on a peer laptop

Problem: three error texts. Before fix: 6/6 calls "unknown error", ~130 s each.

Cause: three roots. "Process closed status 0" = profile busy.

"window is null" = resident Firefox had 0 windows since 10-23 (closed by a human via the red button). "Maximum number of active sessions" = one WebDriver session claimed by 29-40 stdio MCP copies (one per Claude session).

Control: Chrome-MCP did not break; its timeouts coincided with load ~30 (machine-wide, not its own defect).

Solution: one http server under launchd owns the session; call lock in mcp-proxy; wrapper shuts the proxy down; window restored via Apple Event `reopen`. After fix: two HTTP clients x 3 addresses, 6/6 in 15 s. 33-agent workflow found an init race (closed) and a shared tab (open).

Rejected with evidence: "`mcp_lazy_audit` is false green". It judges config; config was correct; it makes no health claim.

Open: no per-session tab isolation, test does not check it; port has no auth and no DNS-rebinding protection; reboot unchecked; sessions started before 18:49 hold old copies (one held the lock 30 min).

Pattern: N stdio copies of a stateful MCP = N claimants, 0 owners. Move to one http server per machine.

## 2. Fleet SSH (10-20..10-26)

Problem: laptop ssh config block dated 10-02 (old port); every daily parcel = `apply-failed`.

Cause: block refreshed only during a parcel run (no own healer). Exit status always 1 because unconnected family nodes counted as failure. An old parcel would have overwritten v1.2 on two nodes (sender decided over a newer receiver).

Adjacent: two bus journals differing only in letter case hung bus sync 10 min; merged +1721 lines; lowercase-name source found in one node's cron.

Solution: `fleet_ssh` 1.2.x -> 1.3.0: `client_heal`; exit over connected nodes only; version judge `newer_local_reason`. Parcel DONE on 5 nodes; matrix 20/20; code panel 4/5; retro 6/6. Fleet order done on 5 of 8 nodes, reported as such by the panel.

Open: family nodes 0/3; their bus robots silent 23 days; 4 parcels without tier bounce.

Pattern: exit code denominator = connected set; a config block needs a healer independent of the delivery channel.

Pattern: detector without executor = growing debt; give each arriving work class a standing executor and a daily batch.
