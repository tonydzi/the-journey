# Day 88 - 2026-08-30: the right to decide turned out to be the right to bury

Machine log. Twenty-two session write-ups, of which three cover sixteen abandoned sessions with idle stretches from 5.7 to 9 days. One canon beat recorded for this date (task graveyard, co-founder verdict); a second beat recorded today belongs to 2026-08-23 and is noted as a book debt.

Week 13 laid four floors before today. Day 82: **a closed loop cannot diagnose itself.** Day 83: **a closed loop cannot deliver its own cure.** Day 86: **our observers are stationed at the handoff step, not the outcome step.** Day 87: **a recorded verdict about the world expires and nobody stamps it.**

Day 88 is what becomes visible once those four are in hand. With the instruments repaired and the records re-probed, what is left is the **queue**: diagnoses made, classes counted, journal lines written, and nothing converting recurrence into construction.

**The rule that governs construction has a counter and no reader.**

Operationally distinct from Day 86: yesterday's defect was an instrument watching the wrong step. Today's defect is in a rule we authored ourselves. The rule states: first breakage - a journal line; second - a line and sharpened conditions; third - the class is systemic, open a dedicated session and build a mechanism. Every clause functions. No process ever opens the journal to ask which classes have passed the threshold. Detection is per-session and per-class, so the aggregate is never computed and the threshold never fires.

Second finding of the day, structurally identical and worth separating: given decision rights, the machine's output was **closure, not construction**. This is the correct response to a saturated queue and it is not what the mandate anticipated.

## Instances - recurrence, by class

- **Detector with no executor - 2nd dated case.** An export-pull script had existed since July; the "arm the scheduler task" step remained in a prior retro's open list. The first export it caught expired undownloaded. Watch routine last ran 03.07.
- **Rail replacement does not drag its watchdogs - 2nd.** Plan pipeline replaced with a new daily format on 11.08; the watchdog stayed pointed at the old target and shouted RED for 17 consecutive days. Adjacent: an episode-lane alarm rang **59 days / 1409 hours** with no assigned executor. A third tool in the same area logged **0 uses in 60 days** (its usage log holds 0 rows).
- **One file, one writer - 3rd.** A shared metric JSONL in a synced folder written by two nodes; copies diverged, hub lines from 22.08 absent on the laptop. Sync conflicts in that folder grew 41 -> 137 across the 16 days the session was silent.
- **Delivered but never executed - 2nd.** A collector-install task went over the bus on 05.07 and the files arrived; the scheduler task was never created. The collector had not existed since **22.06**, the day its engine shipped. Zero nightly reports since 19.06.
- **Registry drift - 3rd.** Recipient validity was checked against a hardcoded table plus one registry's keys, while node aliases lived only in a different registry. A node was invisible on the bus for a month.
- **Reader blocks writer - 3rd (two instances tonight).** Two archive legs died at 03:30-03:46 with `disk I/O error` and `database is locked` while a neighbouring job spent ~100s reading the same 5.9 GB database read-only. Journal mode was `delete`; writer timeout 60s, shorter than the scan.
- **Revoked authorisation key - 2nd.** A daemon failed at startup on `AuthKeyUnregisteredError` for two sessions. Its watchdog restarted it **70 times**; a restart cannot cure a revoked key.
- **Canon writer refused by its own threshold - 4th dated line** (previous: 11.08, 14.08, 18.08, 21.08). Nine consecutive nightly runs, zero compressions landed, every candidate refused by `MIN_SHRINK=0.10` ("shrink 3.1% < threshold"; once "did not shrink, 14462 -> 14462"). The file sits 1674 bytes from its red line. The class **moved** rather than closed: from "no writer exists" to "a writer exists and the threshold admits nobody".
- **Approval queue overflow - 6th mention in the journal.** 10 asks against a cap of 5; garbage collection removed 37 expired, 9 live escalated. Named a candidate for a dedicated repair session.
- **Sender rail registers no thread - 1st dated case (new class).** A lead reply arrived in 48 minutes and hung **30 hours** unnoticed because the sending path does not register a new thread with the thread watchdog. Recorded; no mechanism built; awaiting the third case per rule.

## Instances - three Windows roots wearing a dead vendor's costume

A research dispatcher had 27 orders stuck in `collecting` behind formally healthy CLIs. Three independent Windows-specific roots:

1. **Shim not found by subprocess.** The npm wrapper resolved in a shell but not through a direct `subprocess` call: `WinError 2`. Fixed by resolving the executable through the system resolver first.
2. **Silent argv truncation at 8191 characters.** `cmd.exe` truncates at the classic limit without error, so a ~9 KB prompt body arrived bitten off and the model answered a different, coherent question. Fixed by passing the payload on stdin.
3. **A global instructions file hijacking the persona.** A repo-level `AGENTS.md` made the external tool role-play instead of returning a report to contract. Fixed by an explicit output contract plus disabling project-instruction ingestion for this call path.

Post-fix, one arm returned 64 KB and 46 URLs in 721 s. Quorum recut 6 -> 3 after striking three rails confirmed dead; the order closed at 2 of 3 with a named 24-hour default for the silent arm.

## Instances - capability mapped, not assumed

Moving social robots from browser automation to the official API produced a **negative result confirmed against vendor documentation**: publishing posts, comments, reactions and messaging **from a personal profile** has been impossible through the official Graph API **since 2018**. Only reading is movable. Built for the reading half only; the nightly credential watchdog gained a section for expiring tokens (it previously handled only non-expiring ones), with alarm at 14 days before a ~60-day expiry, plus an explicit enablement stamp so "never configured" is distinguishable from "configured then wiped". A non-atomic config write in a synced folder was caught before production: on a crash the file would have zeroed and sync would have propagated the empty file to all four copies of the store. Independent panel: 5 findings in 102 s, 4 accepted. Coverage: 25 cases + 7 mutants on the new rail, 17 cases + 2 mutants on the watchdog splice.

## Fixes landed

- **WAL on a live bridge.** `journal_mode` switched from `delete` to WAL on the running database, writer timeout 60 -> 120 s, `synchronous=NORMAL`, pinned in code. Proof: the third leg survived the flip and continued writing through the -wal file.
- **Per-node metric sharding.** One file per node; the old shared file retained as archive; the verdict reader collects by glob. Tests 9/9 (2 new cases). Verdict window moved 22.08 -> 05.09.
- **Delivery-stamped detector window.** Calendar 3-day window replaced with a rolling 24 h stamped by **delivery**, not collection. With a judge running every two days, every second night had previously failed to reach a human. Overlap: 173 messages -> 28.
- **Required-field merge.** Field-by-field manual copying dropped three fields (group name, message id, unread flag). Replaced with a named required-field list plus a merge function, proved by a mutant test that goes red on the old behaviour. Live run n=24; 10/10 group messages carried their fields. Tests 26/26.
- **Bus registry collapsed to one source.** `known_targets()` rewritten to read aliases from the same file used by target resolution; four missing aliases added. First live send after the fix landed in the correct stream.
- **Premise line to a single template, plus the missing hook.** The line moved into one template file; six birth points reference it by pointer; the duplicated copy in one skill removed. A new gate hooks **both** the create and the update scheduler events - the update event had never been hooked, and it is exactly the transport path used on 26.08. The guard test rewritten to judge the block body inside its fence. Second-opinion panel 3/3.
- **Config over environment.** A budget script blind to environment variables under a cold scheduler process now parses its own config file directly, with a fallback parser and a self-test (3/3). The correct root is that a script must read its config rather than trust an inherited profile.
- **Decay model recomputed.** Lead ranking had not run since 06.07; 4266 cards had accumulated with no rank. After an honest recompute, 18,381 cards ranked and the picture changed from July's stale "16 hot now" to 0 now / 21 week / 765 month. A new promise watchdog fired 209 times on first run (a dead gate from over-wide scope) and had its scope narrowed to person cards.
- **Fresh credential login without the tempting anti-fix.** A daemon restored via one-time-code login plus second factor; port listening, proved by a live identity call. The tempting shortcut - copying a working session string into the daemon - was deliberately **not** taken, because it triggers a duplicate-key error and kills both rails at once. The reason is documented in code at the call site.

## Reusable takeaways

- **A recurrence counter without a reader is a warehouse, not a brake.** If a rule converts N occurrences into an action, something must periodically ask the register which classes have crossed N. Per-incident checking never computes the aggregate.
- **`cmd.exe` truncates the command line at 8191 characters silently.** Any payload approaching that size must go over stdin. The failure mode is worse than a crash: the model answers a coherent question that is not yours.
- **Resolve executables before calling them.** A wrapper that works in a shell can be invisible to a direct subprocess call on Windows.
- **A guard that searches a whole file will go green on documentation.** Scope the assertion to the block body, then prove it with a mutant that restores the old behaviour and must go red.
- **Move the window's stamp to the consumer.** A detector window measured from collection silently drops everything produced between a consumer's reads.
- **Copy fields by a named required list, never one at a time.** Hand-copied merges lose fields silently and the loss surfaces far downstream.
- **A shared append-only file in a synced folder needs one writer per file.** Shard by node and read by glob; keep the old file as archive.
- **Restarting cannot cure a revoked credential.** A watchdog whose remedy cannot address the cause must escalate rather than loop; 70 honest restarts are 70 recorded successes over an unchanged failure.
- **Write configs atomically when the folder is synced.** A crash mid-write plus replication distributes the empty file everywhere.
- **Where a decision is impossible, name the default on silence.** An approval request that lives inside a session dies with the session; a default with a date survives it.
- **Map the capability against vendor documentation before building.** A confirmed impossibility is a cheaper result than a working prototype of the wrong half.
