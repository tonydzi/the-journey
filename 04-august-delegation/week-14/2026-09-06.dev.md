# Day 95 - 2026-09-06: nothing was broken, and the queue grew anyway

Machine log. Eleven recovery write-ups across three nodes, covering fifty-nine abandoned sessions: hub 52 (8 batches), anchor node 2, peer laptop 5. Canon beats for this date: none - the canon has beats through 2026-09-04 and nothing for the 5th or 6th, which is a named gap rather than a silent skip. Sources for this chapter are the eleven write-ups plus the day ledger and the live wall dump.

Week 14 ladder so far: Day 89 - one object present in many copies, counted as many. Day 90 - a prohibition with no named author. Day 91 - a stale inventory of our own holdings. Day 92 - a verdict read off something adjacent to the subject. Day 93 - an instrument aimed correctly that had never been tested on its ability to fail. Day 94 - every reading has an age and nothing asked for it.

Day 95 closes the week by inverting the method. The previous six days audited **instruments** and found a defect every time. This day audited **workers** - ten nightly routines, by instruments rather than by their own transcripts - and found zero rotten.

The finding is the absence of a finding. Ten healthy routines coexist with a funnel taking in 151 seeds a day and releasing 2, a task registry up 62% in eleven days, and three sessions on a peer node parked on a single human's hands.

The durable rule: **health and throughput are independent properties, and this fleet instruments only the first.** No watchdog anywhere answers "arrival rate vs completion rate". Each instrument reports honestly about its own patch; together they never form an answer to "are we keeping up".

Second-order note for anyone copying this architecture: six days of correctness fixes each added one more mechanism, card, or item that eventually requires a human approval. Correctness work grows the queue at the human valve. That cost is not visible in any correctness metric.

## Incidents

### 1. Ten nightly routines audited by instruments; zero had rotted

- **Problem.** A nightly recovery pass had 52 abandoned hub sessions queued across 8 batches, ages 1.1-27.9 days, and was expected to find rot.
- **Cause.** No defect in the routines. All ten executed their contracts: boundaries held (no run touched shared infrastructure headless), delivery verified by fact rather than return code, model routing obeyed literally (cheap model for mechanics, expensive model delegated only for authorial voice), and fallback rails used when the session's tool set failed to load.
- **Solution.** Verification was done through instruments rather than transcripts: code reads for the inbox robot, a live connector call for the watchdog, a registry diff for the digest, a live third-party API call for the funnel drain, a status journal for voice triage.
- **Pattern.** A run's own retelling is its own testimony. Audit a worker the same way you audit an instrument - with a second source.

### 2. `robot-done` marks an item planned rather than executed

- **Problem.** Seven runs of the cross-machine inbox robot (PLAN-ONLY mode) cleared bus items with 4-10 `robot-done` calls each. The bus now answers "no pending tasks" while a Tier-1 fix from the previous day is objectively unapplied.
- **Cause.** The robot calls `robot-done` immediately after writing the item into the daily plan. The only watchdog holding the item in view releases it at the moment of planning. Downstream, the item exists solely inside a ~90 KB markdown plan file that tomorrow's run replaces.
- **Solution.** An addressed card was filed naming the file, the fix, and a DoD requiring a proven red test run. The evidence is in code: the review object has no timestamp field collected, last-move is computed from comments only, no test file, no deploy parcel.
- **Pattern.** "Removed from the queue" and "executed" must never share a name. A planner must hand the item to an execution watchdog rather than close it itself. Related cost, measured the same day: 127 comments against 7 reviews in third-party pull requests, because the watchdog is blind to the review object and keeps calling us into threads we already answered.
- **Honest boundary.** The plan was eight hours old and its human was asleep. This is an architectural hole, not a discipline failure.

### 3. A connector watchdog wrote UNKNOWN for 27 days under an overall GREEN

- **Problem.** Nine consecutive runs of the daily connector watchdog reported the calendar as UNKNOWN while `overall: GREEN`. The watchdog is silent on green by contract, so nobody knew one connector of five was unobserved for 27.8 days.
- **Cause.** Two compounding defects. (a) The calendar is probed through an MCP session tool; a headless scheduled run loads a different tool set, the tool is absent, and the honest rule "environment is not death" writes UNKNOWN. (b) UNKNOWN does not affect `overall` and **does not age** - the store holds the last run's status, not the age of the last *successful* check, so one miss and 27 days of blindness are indistinguishable.
- **Solution.** A live call inside the audit returned five calendars: the connector is alive, the instrument is broken. Card filed with a two-step cure - a deterministic probe that does not depend on the session tool set (the pattern already used for mail, which never returns UNKNOWN), plus an age-of-last-success field per connector - and a DoD requiring the gate be shown red first.
- **Pattern.** UNKNOWN must age. A status without an age is not a health signal.
- **Self-serving check.** The convenient conclusion ("the calendar died a month ago") was refuted by the live call before it was written down. Half the alarm survived: the blindness is real, the death is not.

### 4. The content funnel takes in 151 seeds a day and releases 2

- **Problem.** `posts.jsonl` holds `new = 644`, `done = 72`, `written = 35`, `frozen = 1709`. Growth over the last 24h: +151. Drain per nightly run: 2.
- **Cause.** Asymmetric cost. The input rail is automatic and cheap (cross-machine session capture plus the voice hub); the output rail is expensive and per-item (gates, platform matrix, human approval for public channels). The routine was created 2026-08-04 against a measured root of 70 seeds in 26 days; the root has scaled by an order of magnitude while the drain has not.
- **Solution.** No code fix. The fork was escalated to the owner with three options (cut input / accelerate output / reclassify the funnel as an archive and switch off the "new" counter) and a stated preference for cutting the input.
- **Pattern.** When a pair of routines is unbalanced, per-run discipline cannot compensate. The drain's discipline is exemplary - live `gh api` verification of the artifact instead of trusting the seed, gate failures rewritten in the same pass, WARN honestly distinguished from FAIL, and the growth during its own run reported out loud - and it is still 75x slower than the input.

### 5. A backlog digest ran every night while the queue grew 62% in eleven days

- **Problem.** Independent measurements: 2026-08-26, 429 live cards / 53 P0 (36 unique); 2026-09-06, 697 unfinished / 146 P0. The digest ran nightly throughout, on the correct source of truth, with delivery surviving connector death via a Telethon fallback.
- **Cause.** The digest has no feedback on effect. It measures queue size and never measures whether delivery changes the rate of closing.
- **Solution.** No new card - RECALL showed the theme already covered by live registry cards (duplicate `repair-*` cards on one class, ~290 cards with no done-criterion) and a queued class solver. Filing an eighth "the backlog is growing" card would be the exact duplication the digest itself counts.
- **Honest boundary.** "The digest is useless" is **not proven**: a digest is an informer, not an executor, and much of the growth is watchdog findings rather than failures. What is proven is narrower: no instrument measures its effect.

### 6. An intentions lane skipped two nights out of six

- **Problem.** Drafts exist for 08-31, 09-02, 09-03, 09-05. September 1 and 4 are absent from both `drafts/` and `candidates/`, so the run did not happen at all rather than failing to write.
- **Cause.** Established 2026-08-22 and already carded: the subscription bucket is exhausted and there is no retry. Card `state: open`, `review_after` overdue by 12 days.
- **Solution.** No duplicate card. Fresh evidence appended to the existing one: the diagnosis is right and the cure never shipped.
- **Pattern.** A correct diagnosis with no executor is indistinguishable in production from no diagnosis. Overdue `review_after` is itself a signal worth watching.
- **Worth copying.** The same routine obeys three expensive rules that are easy to break: it delegates authorial-voice writing to the expensive model and says so explicitly; it discards 16 of 41 sessions as service traffic so a robot's intention is not passed off as the owner's; and it re-checks the send script's behaviour before treating delivery as success.

### 7. Eleven packets and eleven audio files, three weeks apart

- **Problem.** The weekly audio digest produces a packet and then an audio file. Freshest packet: 2026-08-30. Freshest audio: 2026-08-16. Three weeks, two Sundays, no product.
- **Cause.** The audio step is browser-driven and the browser rail does not come up in a headless session (3-6 blocked hits per run). Blocker class `browser-rail-down`, count 48, `queued`, solver raised.
- **Solution.** No new card (dedup against the live class). The first half of the routine is kept: it picks its topic by vault activity, assembles the packet, files it, and even repaired an orphan note by linking it.
- **Pattern.** **Count parity hides date divergence.** 11 packets and 11 audio files is perfect parity by count; a watchdog counting files would report green. Compare the age of the freshest producer output against the age of the freshest consumer output.

### 8. Two alpha judges threw away 22 of 25 candidates and said so

- **Problem.** None. Recorded because the failure mode it avoided is the expensive one: an LLM judge performing productivity by calling chatter signal.
- **Cause/behaviour.** Run of 2026-09-04 over a flagship chat: window 09-02→09-04, 84 messages, 25 shortlisted, 22 discarded as clever but edgeless debate. Verdict stated out loud: "the window is thin". Dedup against home notes performed *before* the verdict, not after.
- **Pattern (reusable).** The unattended contract, verbatim: *"There is NO human here - never ask questions, never offer options, never wait for permission. If you cannot read something, work with what you did read and write one honest line about which check degraded. To ask is to produce nothing."* This is the cheapest known cure for a headless session hanging on a question to a sleeping human. Recommended for every cron-driven agent.

### 9. A nightly janitor died on an ACL mask that an hourly mirror resets

- **Problem.** The anchor node's orphan janitor reached real work and died: `PermissionError` creating a backup lock file. The shared directory shows `user:anton:rwx` under `mask::r-x`, i.e. effective `r-x`.
- **Cause.** Sixth dated case of the class (08-27, 08-29, 08-30, 09-04, 09-06). The emitter was identified on 09-04 and named in a commit: an hourly `rsync -a` mirror performs a `chmod`, which recomputes the ACL mask. Naming it did not disarm it - fewer than two days passed between identification and the next occurrence.
- **Solution.** Manual repair (`setfacl -R -m u:anton:rwx,mask:rwx`), which also unblocked that night's janitor. Evidence appended to the existing class card.
- **Pattern.** "Emitter named" and "emitter disarmed" are different work items. Closing the first and reporting progress leaves the class fully live.
- **Related.** The same node's earlier hardcoded-path defect *was* fixed at the root (engines now read `OBSIDIAN_VAULT` / `IMPORTS_ROOT`), and the real root was the same hourly mirror: `rsync -a` without `-u` overwrote the local patch within the hour, which is why manual fixes kept vanishing.

### 10. A fleet-wide memory index has no nightly writer at all

- **Problem.** One always-loaded memory index syncs byte-for-byte across the fleet and is tidied by nobody.
- **Cause.** A three-way ownership gap. The scope registry (2026-08-23) names the anchor node as sole writer. The hub excludes that project because the anchor owns it. The anchor's nightly runner predates the registry (2026-08-04), never reads it, hardcodes its own exclude list, and targets a different project - a fact its own source comment admits: *"E-index ownership is a separate OPEN QUESTION for Anton."*
- **Solution.** Card filed. The file is not red (76 lines / 11694 B against thresholds of 200 lines / 25 KB), so this is a quiet ownership hole rather than a fire.
- **Pattern.** Two conscientious mechanisms can create a gap by politely deferring to each other. Ownership must be asserted by the *runner on disk*, not only by the config that describes it - config is intent, disk is fact.

### 11. A lost-session scanner uses a five-day floor against a canon of one

- **Problem.** The recovery queue on the anchor node showed 2 candidates where the seed asked for 5.
- **Cause.** `MIN_AGE_DAYS = 5` in the scanner; the skill's canon moved to 1 day on 2026-09-02. Sessions aged 1-5 days are invisible to that node.
- **Pattern.** "The queue is empty" from a stale instrument means "the instrument is blind", not "there is no work". Same family: the same node has two open cards for one scanner defect, filed eight days apart by two runs; the third run correctly declined to file a third.

### 12. A scratch shim outlived its cause and diverged from the repaired engine

- **Problem.** Three files assembled in a scratch directory on 09-01 to route around the ACL/path walls are still present on 09-07 and now differ from the repaired production engines.
- **Cause.** The workaround was created legitimately; the root fix landed 09-03/09-04; nothing removed the workaround.
- **Risk.** One of the three is a copy of the script that writes into notes - a live, write-capable divergent duplicate.
- **Pattern.** Clear the workbench in the same pass that removes its reason. One source, zero copies.

### 13. Three "dead" verdicts refuted the same night

- **Calendar** declared dead for a month → live call returned 5 calendars.
- **Landing page** declared dead on an organisation URL returning 404 → the primary home per the distribution registry answered HTTP 200; the org page is either not enabled or a duplicate.
- **Four memory files** declared orphans because they had no line in the main index → pointers live in the archive index and two hub spokes, and the memory guard reports 0 orphans for that project. The index in question is a hub spoke over ~860 files at 71 lines; "no line in the main index" is not an orphan detector.
- **Pattern.** Yesterday's rule executed the same day: a negative conclusion must carry a date and a surface. All three refutations cost minutes and each overturned weeks of a false world model.

## Counterweight

Real boundaries were named rather than routed around. The skills-catalog submission accepts human authors only; the request has waited 17 hours as a Tier-2 ask rather than being forged. In the hiring-channel memo, sending replies and DMs stays in human hands by platform rule, and only reading, drafting and scheduling of pre-approved posts are automatable; browser automation of posting is named as a permanent-suspension risk in the platform's own guidelines.

Duplicate suppression held all night: sixteen cards were filed in 24 hours (six addressed, ten by breakage class) and zero duplicates, because every write-up ran a live check for an existing solver and found one in four cases.

One convenient conclusion was declined rather than kept: "the backlog digest is useless" was withdrawn as unproven, and the narrower proven claim ("it has no feedback on effect") was recorded instead.

The public wall shows zero posts by the owner for 2026-09-06 against 234 robot sessions in the same 24 hours. The wall crane was under an hour old at chapter assembly and holds entries for 09-05 and 09-07, so the silence is a property of the day and not of the instrument.

## UPD (2026-09-08): two write-ups that arrived after this day closed

Both were delivered to the vault after the Day 95 chapter was committed on the morning of 2026-09-07. Appended rather than merged into the body, per the append-only rule for closed days.

### 17. A watchdog performed 1,583 restarts of a process that could not survive its own launcher

- **Problem.** A dedicated agent browser was raised on 2026-08-19 on its own port, with a connector and a five-minute watchdog, plus a 48-hour measurement window. The session slept 17 days. Between 2026-08-28 and 09-04 the watchdog performed **1,583 restarts** (280+/day, 40 failed starts) while the instrument reported green throughout.
- **Cause.** The launcher backgrounded the browser without detaching it from its parent, so the operating system reaped the whole process tree together with the short launcher script. Measured from the scheduler: browser alive at +12s, dead at +37s.
- **Why green.** The watchdog reports on **itself** - it ran, it launched, it wrote its report. Liveness of the guarded object was never an input to its own status.
- **Second defect found in the same pass.** The shadow run had no harvest date. 406 hours had elapsed of a planned 48; the sample stood at 2 tasks of 20; the instrument honestly printed "too early, still accumulating" - a verdict that sustains itself and can never become "now". The local rule requiring a harvest date on any shadow run was violated by the very run that started the shadow.
- **Third defect, found along the way.** The watchdog had no reporting channel at all.
- **Solution.** All three roots repaired; the measurement restarted; the harvest date assigned and given an alarm.
- **Pattern.** **The health of a watchdog and the liveness of the guarded object are independent properties.** A watchdog whose status is derived from its own execution will report green over a corpse indefinitely, and the restart count is the only visible symptom - which nothing was watching.

### 18. A competitor's delivery formula was extracted into a skill

- **Problem.** None; recorded as a reusable pattern. A competitor sells a second-brain camp at roughly a monthly salary; on substance he teaches what runs here in production across six machines. His advantage is delivery, not content.
- **Extraction.** Six techniques identified from his material - artifact screenshot, contentious claim, checklist, honest curve, edge-of-a-secret, and FAQ-plus-summary - and encoded into a new skill for evergreen guides.
- **Enforcement.** Daily teaching posts must draw at least two of the six; the requirement is a line inside the skill definition rather than a convention.
- **Distribution.** Skill published to a public repository the same pass, teaser filed into the content funnel, entry added to the distribution queue.
- **Pattern.** When a competitor's advantage is delivery rather than substance, the transferable asset is a checklist of their techniques, and it belongs inside the tool that produces the content, not in a note about the competitor.
