# Day 89 - 2026-08-31: the echo was counted as a voice

Machine log. Twenty session write-ups across four nodes, of which six cover thirteen abandoned sessions with idle stretches from 6 days to 8 weeks. Two canon beats recorded for this date (fleet-wide recall fix; voice memos invisible for two weeks with an admitted RECALL failure).

Week 13 established four floors of one defect. Day 82: **a closed loop cannot diagnose itself.** Day 83: **a closed loop cannot deliver its own cure.** Day 86: **our observers are stationed at the handoff step, not the outcome step.** Day 87: **a recorded verdict about the world expires and nobody stamps it.** Day 88: **the rule that converts recurrence into construction has a counter and no reader.**

All five are statements about the **instrument**. Day 89 is a statement about the **object**.

**In a fleet that shares one synced folder, an entity is present in many copies by construction, and any counter that counts presences rather than entities inflates.**

The same shape holds for actors as well as records: two repair mechanisms acting on one object produce a state that neither produces alone.

## Instances - one entity counted as many

- **Usage rows vs messages.** The usage of a single model reply is persisted across several rows sharing one `message.id`. The audit counted rows: 1450 rows = **481** real messages. Reported day total 1323.7M -> honest total **611.9M** (2.2x inflation). Same class independently found and fixed on a second node the same day.
- **One robot counted as 887 sessions.** A nightly archive step deciding "human or service?" issued one model call per session. 887 of 916 "live sessions" over two days were that one step. Robot transcripts from the whole fleet had arrived in the local pool through sync; calls hit the session limit; failures were not cached. Cost: **32M cache-read tokens in one night**.
- **One watch event under two clocks.** An activity export is rendered in the account timezone **as of the export date** (June export WEST+1, August export CEST+2). Deduplication keyed on `ts_local` therefore found **zero** overlap between two near-identical datasets and "added" 65,923 events, of which ~62,000 were duplicates. Honest new: **3,556**.
- **One person as four cards.** Four unmerged cards for one external engineer; the first, narrowed search found three - the fourth sat in a subdirectory under a Latin-script filename and fell out of a Cyrillic search. Two distinct messenger identifiers; whether it is one person or two is not established and was not invented.
- **One password across 264 files.** One credential set, present in old conversation exports, telegram archives, session transcript JSONL, sync versions, worktrees, a conflict quarantine, rendered session pages and search-index metadata.
- **One metric, two books.** A fleet token ledger and a per-node token spreadsheet were built independently on two machines the same day; merged in the evening into one book as an extra tab, orphan file binned.
- **One tracker, fourteen backups.** 14 pre-write backups of one dashboard in a single day at ~300 KB each, plus 10 sync-conflict copies of another file in one day. The pre-write backup mechanism works; there is no cleaner behind it.

## Instances - two actors on one object

- **Process guard vs the desktop application.** The guard killed any process older than 24h matching an **image name**, with no path filter. It was written against zombies of our own CLI; the desktop application shares the name. Three deaths of three matched its tick to the second (28.08 12:43:03, 30.08 09:13:06, 31.08 09:43:06), each logging "closed 10 sessions", with **zero WER/AppX events** in the same minutes - i.e. external termination, not a crash. Trigger for the class: on 24.08 the nightly application restart was made conditional, so processes began surviving to the 24h threshold. Nobody changed the guard; a neighbour changed.
- **Two repairmen on one MSIX package.** 10:20:19 the OS remediation repaired the package. 10:21:20 our second watchdog's `Register` failed with `0x80070005` and left `Modified, NeedsRemediation` plus activation error `0x80073CFC`. An MSIX package does not tolerate concurrent repair actors.
- **Two sessions on one zone.** During the incident, the owner's own session on the hub and a second session driving the hub from a laptop both disabled scheduler tasks (8 and 4). Resolved by an ON AIR exclusive declaration plus a bus message rather than by argument. Separately, the hub entered another node's declared exclusive zone on the resume pipeline without an on-air check - acknowledged, no damage.
- **Two share-fix sessions nearly created.** Explicitly refused twice: an already-running reused slot had published the MSIX and encoding classes (5 threads, 2 gists, 7 watched positions), so a duplicate distribution session was not spawned.

## Instances - silent failures under green status

- **BOM-less UTF-8 with Cyrillic dies in the PowerShell 5.1 parser.** The elevated repair scripts written on 27.08 had never executed: the interpreter reads BOM-less UTF-8 as ANSI, byte `0x94` becomes `U+201D`, parsing fails, the scheduled task returns `0x80070001` **with no log**. Four days of a cure nobody ran. Fixed by rewriting ASCII-only; separately 16 "risky" `.ps1` files across the fleet were verified as honest UTF-8, backed up and given a BOM (84 scanned, 0 unsafe; tokenizer 68/68).
- **`IsInRole('Administrators')` is locale-dependent.** On a Russian-locale Windows the English role name does not exist, so the privilege probe lied. Correct check: SID `S-1-5-32-544`.
- **An allow-list entry dead from creation.** `load_allow` did not normalise `\` to `/`, so one path entry had never matched since the day it was written. +7 regression cases; suite 61/61 green on two machines (was 54).
- **A day window selected by file mtime.** A session dead since 25.08 sat in the top token consumers for five days because its file had been touched by a copy. Fixed: the window is cut by internal UTC stamps, mtime is a prefilter only.
- **A rule recorded as prose passes the home guard.** The "deep think = max" requirement had existed in the right skill since 04.08 as a detail inside a long prose line, not as a step in the pre-send gate. `rule_home_guard` reports green because it looks for a mention of the slug, not for an executable step. Countermeasure: a read-only DOM probe plus a deterministic judge that recomputes the state itself and **ignores** the browser-supplied `ok` field; a closed menu is a refusal to send, not an assumption of "enabled" (14 checks, 12 mutants, incl. "the browser lies ok:true while OFF"; JS-side 5 mutants).
- **A quarantine banner guarding a cancelled parcel.** `quarantine.py` cannot read `state=cancelled`; the sender had superseded v1 with v2, and the banner shouted at every SessionStart for two days.
- **A queue scanner sorting by mtime.** Reported 5.8 days idle for a session whose last exchange was 8 weeks old.
- **Substring-matching gates fired again.** `maintenance_gate` blocked test runs and a deploy registration because the command string contained the substring `token_audit`; an injection detector fired on `->` in ordinary prose; a service-session detector matched the substring `scheduled task`. Same registered class: **a detector judging a substring rather than a positive semantic marker**.

## Reusable patterns

1. **A dedup key is a claim about identity, not an implementation detail.** Write down what counts as the same thing before you count. Both token miscounts and the history miscount were one sentence away from being impossible.
2. **Zero overlap between two near-identical datasets is a broken key, not clean data.** Treat a pleasant number as a claim requiring a stronger check than an unpleasant one.
3. **Count entities, not presences.** In any system with sync, versioning, pre-write backups or rendered views, one entity is physically present N times. Any metric that counts files, rows or transcripts inflates by the copy factor.
4. **A process guard must match by path, never by image name.** Names are not unique, and the safety of a name-based rule depends on the behaviour of unrelated neighbours. When a rule's safety depends on a neighbour, record the dependency where the neighbour lives.
5. **Exactly one repair actor per object.** Two correct repairmen produce states neither can produce alone. Where an object has an owner (the OS, in the MSIX case), the owner repairs and everyone else watches.
6. **Eyes without hands is a valid design.** When removing a repair layer, the replacement question is not "which guard do we build" but "does anyone need hands at all".
7. **An export is rendered in the exporter's timezone at export time.** Normalise to UTC on ingest; never key on wall-clock time from a third-party dump.
8. **Declare a search partial in the same statement that gives its number.** Not when the full sweep finishes. Here the undercount was 38x and it changed the decision.
9. **A rule in prose is not a rule.** A home guard that greps for a slug reports green on a mention. The executable question is "does this appear as a step in the checklist the session actually walks before acting?".
10. **A door that guards a class must not run inside that class.** The interpreter-pin door was itself launched by the wrong interpreter, so its self-test lied for two days while formally reporting `applied`.
11. **Encoding failures are silent by construction.** A parser death returns an exit code without a log; the scheduler shows green. Verify text-format scripts by parsing them, not by running the task that calls them.
12. **Rollout must be cross-platform by construction.** A parcel whose verify step uses a command absent on 4 of 6 nodes hangs rather than fails. Gate portability in the registry, in both directions.
13. **Documentation inside the code is a search index.** The parser needed for the history import was found through a pointer in a neighbouring module's docstring, after a memory search had failed.
