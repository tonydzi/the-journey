# Day 90 - 2026-09-01: we mistook our fence for the horizon

Machine log. Fifteen session write-ups across four nodes, three of which cover fifteen abandoned sessions with idle stretches from ten days to three months. One canon beat recorded for this date (fifth peer pilot launched, first on a competitor stack).

Week 13 established four floors of one defect, all of them statements about the **instrument**. Day 89 moved down to the **object**: an entity present in many copies inflates any counter that counts presences.

Day 90 moves down again, to the **record**.

**A constraint recorded in our own files is indistinguishable, at read time, from a constraint imposed by the world - and nothing in the pipeline stamps the author.**

Day 87 said a record about the world expires. Day 90 says a record can be well-formed, internally consistent, never expired, and still have never been about the world at all.

## Instances - our own fence read as the world's edge

- **Source map held 3 of 6 ATS providers.** Lever, SmartRecruiters and Recruitee were absent from `jobs_spec_data.py`. Consequence: employers hosting on those providers - Palantir and Binance among them - produced zero rows in every table, report and answer for the whole of August. The list had grown by encounter (add a provider when one is noticed) rather than by coverage (enumerate the provider space, then subtract). Both growth modes yield a well-formed file.
- **Seven consecutive HTTP 400s read as "no access."** `gh api /search/code` failed identically seven times. Cause: Git Bash rewrites an argument beginning with `/` into a filesystem path (MSYS path conversion), so the endpoint arrived mangled and the API correctly rejected it. Proved by `gh` itself. Fix same session, rule recorded in the docstring: from Git Bash, call `gh api` without a leading slash. Class first dated occurrence.
- **A browser carve-out written as fact.** The `/firefox` matrix carried a written exception "Facebook: Chrome by necessity" alongside four repetitions of the standing order "always Firefox." The exception encoded an unproved hypothesis about ban risk. It kept the `fb-reply-daily` lane down for 12 days (last successful reply 2026-08-19 17:49, per `fb_guard.db`). Remediation was a single login in the Firefox profile; the carve-out is cancelled in canon.
- **`idle_days` derived from `st_mtime`.** `retro_lost_scan.py` line 71 computes age exclusively from file modification time with no fallback to in-file timestamps. The queue reported 10.6 days idle for five sessions whose first in-file entries are 2026-05-27, 2026-06-15, 2026-06-18, 2026-06-19 and 2026-07-07 - a true idle range of 49 to 97 days. Root: 632 of 850 transcripts on that node carry mtime `2026-08-21 13:49:07.824`, identical to the millisecond, from a mass rewrite. Scanner window is `MIN_AGE_DAYS=5 … MAX_AGE_DAYS=30`, which puts a hard date on the loss: **2026-09-20**, when all 632 leave the window simultaneously. Third dated line of the "instrument was lying" class; systemic repair filed.
- **A mass-delete guard's definition of recoverable.** The gate flagged 120 files for deletion, 89 of them "with no recoverable copy," where recoverable means present in `_originals`. A check with a second instrument found all 89 in `git HEAD`. The guard's wording is more frightening than the situation.
- **Sorting by "newest first" is dead** for those same 632 transcripts, because the sort key is constant across them.
- **The scanner does not check whether a retrospective already exists.** Two of five offered candidates were already written up. The retrospective routine also lands in its own queue - a steady tax of about one unit per run.

## Instances - real constraints, named and not crossed

Recorded deliberately, because the day's counter-move is *attribute every ban to an author*, not *break every ban*.

- **Discord connector: not built.** Both technical routes fail on a real boundary - a bot requires admin rights on servers we do not control, and a self-bot with a user token violates the service terms and risks the account. Telegram channels plus aggregators cover the same need legally.
- **Vendor application caps are real.** One lab allows 5 applications per 180 days (3 spent); a second 3 per 90 days (exhausted); a third 5 per 90.
- **A professional network holding part of the market is banned to the operator**, so roles reachable only behind that wall are out of scope.
- **The enterprise audio-generation API has no public tier.** Programmatic access exists only through a paid pre-GA enterprise product, which makes it a purchase decision, not an engineering one.

## Instances - silent failures under green status

- **A diagnostic call that mutates.** `cron_heartbeat.py` invoked with no arguments writes the heartbeat instead of printing it, and overwrote the previous day's mark. A read with a side effect; second instance of this class in a week.
- **A sync conflict silently dropped an appended line.** A line written to the breakage journal was absent from the live copy moments later. The first cause named was wrong - a familiar heredoc class, visible in the tail of the same file, was assigned and even recorded. The real cause, found by a catch-up `grep -rl`, was a Syncthing conflict between two writers of one synced file resolved in favour of another node's version. Conflicts on that file date back to at least 2026-08-11. New class: `breakage-journal-sync-conflict-eats-writes`.
- **A bus order landed on a disabled routine.** An order to add a source to regular mining was sent over the bus on 2026-08-27 and landed on `fb-watch-daily`, stopped by order on 2026-08-06. No acknowledgement returned, and no mechanism checks for a missing acknowledgement.
- **Two independent rails agreed a dead feed was alive.** Both named `ai-jobs.net/feed` as live; it returns 404. Agreement between rails is not corroboration.
- **A writer holding its own copy of the source of truth.** `sources_sheet.py` kept private copies of the ATS URL templates and raised `KeyError: lever` on the first new provider. Caught by a test, not production. Copy deleted; single source is `jobs_spec_data.PAT`.
- **A deduplication check hit the wrong registry path** and returned "no duplicates"; the correct path held 11 crypto entries. Empty from one location is not "none."
- **The anchor node's nightly janitor did not complete on either of two consecutive nights**, terminating on `You've hit your session limit`. Heartbeat frozen at 2026-08-30 03:17. Cause not investigated - out of the light profile's mandate, and recorded as such.
- **Access-permission rollback on the anchor node, fourth dated case.** The 2026-08-30 repair held under 48 hours. Manual `setfacl` repair is now recorded as a tax rather than a cure; the tracking card's `review_after` was already overdue.
- **A loaded git index as a live mine.** `vault_backup.py` runs `git add -A` before commit; when the commit is blocked by the mass-delete guard, the index stays loaded with another actor's deletions, so the next narrowly scoped session risks committing them under its own message. Found by checking `git status` out of habit, not by analysis. Bypass deliberately not taken: confirming another actor's irreversible operation is a Tier-2 decision.
- **Eight finished drafts from 2026-08-17 had never entered the posting pipeline** (15 days). A twelve-post series stalled at 6 of 12, silent since 2026-08-25 with seven topics remaining.
- **The nightly zero, case 2.** The mail watchdog reported `count:0` against a live message. Evidence inside the state: `labels:[a,a2,bb]`, while this node scans `--label a` only, so the zero was written by another node's scanner through the shared folder. The "session had no network" hypothesis is rejected. No repair mechanism built - case 2 of a 3-case threshold.

## Reusable patterns

- **A list has a growth mode, and the mode is not visible in the file.** Encounter-driven and coverage-driven lists look identical. Record the mode next to the list, or enumerate the space once and subtract.
- **A source qualifies by measured catch, not by a valid response.** "Responds" is a property of a server; "yields what we need" is a property of the world. 158 boards proved the gap.
- **A repeated identical refusal is suspicious.** Real failures vary. Seven byte-identical errors indicate a deterministic transformation on your own side; instrument the near side before attributing the boundary to the far side.
- **A ban is a claim with an author and an expiry.** Before building a workaround, ask the owning system live and record who wrote the constraint. If the author is us, it is a line, not a boundary.
- **Never mark rows by position in a table that another process rebuilds.** Use a stable key, or gate the write on the age of the position cache.
- **Do not derive idle time from `st_mtime` in a synced or mass-rewritten tree.** Prefer timestamps inside the payload; `st_mtime` records delivery, not authorship.
- **A guard's definition of "safe to lose" must be verified against every store that holds copies**, not the one the guard was written against.
- **Rights, qualifications and permissions must exist as an explicit list.** An unwritten right silently narrows a search space, and nobody ever chose that narrowing.
- **An order sent over a bus needs an acknowledgement check, not an acknowledgement.** The failure mode is a live sender and a disabled receiver, and it is silent on both ends.
