# Week 14 (Aug 31 - Sep 6) - the week the object stops being one

> *A dedup key is not an implementation detail. It is a claim about what counts as the same thing in the world - and we had never written that claim down.*

Неделя 13 разобрала слой обслуживания на четыре этажа и каждый раз находила дефект **в приборе**: он не может поставить себе диагноз, не может доставить себе лечение, стоит в точке передачи вместо точки результата, живёт по протухшей записи. Воскресенье добавило пятый: правило, превращающее повторение в постройку, имеет счётчик и не имеет читателя.

Неделя 14 открывается на этаж ниже, туда, куда предыдущая не заглядывала. Прибор может быть исправен, метод верен, а число - ложным, если **объект присутствует в системе больше одного раза**.

У флота из шести машин, живущих в одной синхронизируемой папке, это состояние по умолчанию. Транскрипт чужой машины лежит на моей. Бэкап трекера лежит рядом с трекером. Версия файла лежит в корзине версий. Отрендеренная страница сессии лежит рядом с самой сессией. Копия карточки человека лежит в подкаталоге под другим алфавитом. Каждая копия по отдельности законна и создана правильным механизмом. Вместе они означают, что **любой счётчик, который считает присутствия, а не сущности, завышает ровно на коэффициент копирования**.

Понедельник дал этот класс в семи независимых экземплярах за один день. Расход модели завышен вдвое, потому что один ответ хранится несколькими строками с одним идентификатором. Восемьсот восемьдесят семь «живых сессий» оказались одним ночным роботом, которого судья разбирал по кругу. Шестьдесят пять тысяч «новых» событий истории просмотров оказались на девяносто пять процентов дублями, потому что выгрузка помечается часовым поясом на момент экспорта и одно событие получило два разных времени. Один человек лежит в базе четырьмя карточками. Один пароль лежит в двухстах шестидесяти четырёх файлах. Одна метрика получила в один день две независимо построенные таблицы на двух машинах.

И тот же дефект - в акторах, а не в записях. Приложение на главной машине убивал не апдейт и не краш, а собственный сторож, резавший процесс **по имени файла** без фильтра по пути; его правило было безопасным полтора месяца и стало смертельным в тот день, когда изменилось поведение соседнего механизма. А пакет добивала гонка двух ремонтников: штатная ремедиация операционной системы починила его в 10:20:19, наш второй сторож сломал в 10:21:20. Приказ владельца - выключить **все** чинилки абсолютно - и выздоровление, начавшееся ровно тогда, когда от пакета убрали руки.

Контр-ход недели формулируется одинаково для записей и для акторов: **свернуть к одному**. Дедуп по идентификатору сообщения, дедуп по универсальному времени, один регистратор доменов, одна дверь для правок резюме, одна книга флота вместо двух таблиц, список разрешённого по пути вместо имени, один ремонтник вместо двух - а лучше ноль.
